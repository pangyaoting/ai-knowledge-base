# 部署上线指南

> 把项目部署到云服务器，让别人也能访问。
> 建议在阶段 1 代码全部跑通后再操作。

---

## 1. 准备服务器

### 1.1 购买

推荐阿里云或腾讯云的轻量应用服务器（学生机便宜）：

- **配置**：2核2G 以上（跑 PostgreSQL + Redis + NestJS + Nginx 够用）
- **系统**：Ubuntu 22.04 LTS
- **带宽**：3M 以上
- **价格**：学生约 50-100 元/年

购买后拿到：**公网 IP**、**root 密码**（或 SSH 密钥）。

### 1.2 域名（可选）

在阿里云/腾讯云买一个 `.cn` 或 `.com` 域名（约 30-50 元/年），解析到服务器 IP。
没有域名也可以直接用 IP 访问。

## 2. 服务器环境初始化

SSH 登录服务器：

```bash
ssh root@你的服务器IP
```

### 2.1 更新系统

```bash
apt update && apt upgrade -y
```

### 2.2 安装 Docker

**服务器（Linux）上：**

```bash
# 一键安装 Docker
curl -fsSL https://get.docker.com | sh

# 启动 Docker 并设置开机自启
systemctl start docker
systemctl enable docker

# 验证
docker --version
docker compose version
```

> **注意：你自己的 Windows 开发机不用照这个做！**
> 本机环境特殊：Docker Desktop 因虚拟化问题损坏，我们改在 **WSL2 Alpine 里直接跑 Docker Engine**，
> 用计划任务 `WSLDocker` 保活，`keep-docker-running.sh` 负责拉起容器。
> 开发机上启动项目直接双击 `一键启动.bat` 即可，不用手动碰 Docker。
> （Docker 是什么、WSL2 是什么，见《03-阶段1复盘与效率方法论.md》第 4 节）

### 2.3 安装 Node.js（用于 CI/CD 或手动部署）

```bash
curl -fsSL https://deb.nodesource.com/setup_24.x | bash -
apt install -y nodejs
npm install -g pnpm
node -v   # v24.x（>=20 均可）
pnpm -v   # v11.x（>=9 均可）
```

> 本机开发环境实测：Node v24.19.0 + pnpm v11.21.0。
> 服务器上装 20 或 24 都行（CI 用的是 20，两端都验证过）。

### 2.4 安装 Nginx

```bash
apt install -y nginx
systemctl start nginx
systemctl enable nginx
```

## 3. 部署项目

### 3.1 拉取代码

```bash
cd /opt
git clone https://github.com/你的用户名/ai-knowledge-base.git
cd ai-knowledge-base
```

### 3.2 配置环境变量

```bash
cp .env.example .env
nano .env
```

生产环境需要修改：

```env
# 数据库密码改成强密码
DB_PASSWORD=你的强密码
DATABASE_URL=postgresql://kbuser:你的强密码@localhost:5432/knowledge_base?schema=public

# JWT 密钥改成随机字符串（用 openssl rand -hex 32 生成）
JWT_SECRET=用openssl生成的随机字符串
JWT_REFRESH_SECRET=另一个随机字符串

# AI API Key
DEEPSEEK_API_KEY=sk-你的真实key
SILICONFLOW_API_KEY=sk-你的真实key
```

生成随机密钥：

```bash
openssl rand -hex 32
openssl rand -hex 32  # 再跑一次，两个密钥不一样
```

### 3.3 启动数据库

```bash
docker compose up -d
docker ps   # 确认 postgres 和 redis 都在运行
```

### 3.4 构建并启动后端

```bash
cd apps/server
pnpm install
npx prisma generate
npx prisma migrate deploy   # 生产环境用 deploy（只应用已生成的迁移，不创建新迁移）
pnpm build
```

用 PM2 守护后端进程：

```bash
npm install -g pm2
pm2 start dist/main.js --name kb-server
pm2 save
pm2 startup   # 设置开机自启，按提示执行输出的命令
```

### 3.5 构建前端

```bash
cd ../web
pnpm install
pnpm build
```

把构建产物复制到 Nginx 目录：

```bash
cp -r dist/* /var/www/kb-web/
mkdir -p /var/www/kb-web
cp -r dist/* /var/www/kb-web/
```

## 4. Nginx 配置

### 4.1 创建配置文件

```bash
nano /etc/nginx/sites-available/kb
```

写入：

```nginx
server {
    listen 80;
    server_name 你的域名或IP;

    # 前端静态文件
    root /var/www/kb-web;
    index index.html;

    # 前端路由（Vue Router history 模式）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理到后端
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE 流式输出必须的配置
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
        chunked_transfer_encoding on;
    }

    # Gzip 压缩
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml text/javascript image/svg+xml;
    gzip_min_length 1000;
}
```

### 4.2 启用配置

```bash
ln -s /etc/nginx/sites-available/kb /etc/nginx/sites-enabled/
nginx -t          # 测试配置
systemctl reload nginx
```

现在访问 `http://你的IP` 应该能看到页面了。

### 4.3 配置 HTTPS（有域名才需要）

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d 你的域名
```

按提示操作，Certbot 会自动配置 SSL 证书和续期。

## 5. GitHub Actions 自动部署（CI/CD）

项目根目录的 `.github/workflows/deploy.yml` **已经写好**（阶段 1 完成时创建），结构如下：

```yaml
name: CI/CD

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  # ① 代码检查 + 构建（PR 和 push 都跑，保证不把坏代码合进 main）
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 9
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: pnpm
      - name: Install dependencies
        run: pnpm install --frozen-lockfile
      - name: Type check server
        run: cd apps/server && npx tsc --noEmit
      - name: Build frontend
        run: pnpm --filter @app/web build
      - name: Build server
        run: pnpm --filter @app/server build

  # ② 自动部署（只有 push 到 main 才跑，依赖 ① 通过）
  deploy:
    needs: check
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to server
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: root
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          script: |
            cd /opt/ai-knowledge-base
            git pull origin main
            pnpm install --frozen-lockfile
            cd apps/server
            npx prisma generate
            npx prisma migrate deploy
            pnpm build
            pm2 restart kb-server
            cd ../web
            pnpm build
            rm -rf /var/www/kb-web/*
            cp -r dist/* /var/www/kb-web/
            echo "✅ Deploy complete"
```

**这段 yml 的要点（面试可能问）：**
- `check` 和 `deploy` 是两个 **job**，`needs: check` 表示部署必须等检查通过
- `pnpm install --frozen-lockfile`：严格按 lockfile 装依赖，保证 CI 和本地版本一致
- 部署用 `appleboy/ssh-action`：GitHub 通过 SSH 登录服务器执行命令
- Secrets（`SERVER_HOST`、`SSH_PRIVATE_KEY`）存在 GitHub 仓库设置里，密钥不会出现在代码里

**在 GitHub 仓库 Settings → Secrets 里添加：**
- `SERVER_HOST`：服务器 IP
- `SSH_PRIVATE_KEY`：你的 SSH 私钥（`cat ~/.ssh/id_rsa`）

之后每次 `git push origin main` 就会自动构建部署。

## 6. 常用运维命令

```bash
# 查看后端日志
pm2 logs kb-server

# 重启后端
pm2 restart kb-server

# 查看数据库
cd /opt/ai-knowledge-base/apps/server
pnpm prisma:studio    # 可视化数据库管理

# 备份数据库
docker exec kb-postgres pg_dump -U kbuser knowledge_base > backup.sql

# 恢复数据库
cat backup.sql | docker exec -i kb-postgres psql -U kbuser knowledge_base

# 查看容器状态
docker ps
docker logs kb-postgres
docker logs kb-redis
```
