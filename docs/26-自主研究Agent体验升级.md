# 阶段 4+：自主研究 Agent 体验升级（确认方向 / 先摘要后展开 / 精读缓存）

> 一句话：把自主研究从"创建即闷头跑"升级成**可控、可读、更快**——
> ① 方向拆解完先给你确认，满意才开跑；② 报告交付**先摘要后展开**，不再一屏灌满；
> ③ 精读正文**缓存 + 并行**，同一页面只提取一次，并修掉断点丢笔记的隐患。

---

## 一、需求来源（用户"依次做"清单第 ② 项）

| # | 痛点 | 落地 |
|---|---|---|
| 1 | 创建任务后 Agent 直接开跑，拆出什么方向只能干看，方向不对只能等停止 | **方向拆解 → 待确认**：展示方向清单，确认才研究；可重新拆解/取消 |
| 2 | 报告一次性整篇输出，长报告一屏灌满、重点难抓 | **先摘要后展开**：执行摘要置顶，正文按节折叠（引言/各方向/结论） |
| 3 | 精读慢；多方向读到同一页面重复提取；中断后断点丢笔记 | **精读缓存提速**：URL→正文缓存 + 并行提取 + 笔记成功才记为已读 |

## 二、核心设计

### 2.1 方向拆解先展示确认再跑

新增任务状态 `awaiting_confirm`（待确认）：

```
创建(pending) → runner 拆解方向 → awaiting_confirm（任务停住，job 结束，不占 worker）
   ├─ 确认开始  → pending 重新入队 → runner 读断点（方向已存在，跳过拆解）→ 直接研究
   ├─ 重新拆解  → 清空 progress/directions → 重新入队 → 重新拆解（再花一次拆解 token）
   └─ 取消停止  → stopped + stopReason=cancelled（未开始无报告，前端停止轮询）
```

- 拆解只花一次 LLM 调用（实测 ~250 token），确认/续跑全部走既有"断点续跑"通道；
- 确认时校验结束时间未过；等待确认期间时间窗照常计时（确认越晚可用时间越短，界面提示）；
- 取消语义：`pending`（排队中）与 `awaiting_confirm`（待确认）停止 = 取消（`cancelled`），
  runner 不在跑不会补报告；`cancelled` 的任务仍可"继续研究"直接开跑。

### 2.2 输出先摘要后展开

- 新增 `agent_tasks.summary` 列（执行摘要）；
- 报告组装顺序改为：**摘要（最高优先级）→ 引言 → 逐方向润色 → 结论**，
  组装预算耗尽时摘要优先于小节润色——研究怎么停都先交付"能一句话看懂"的摘要；
- 前端：摘要卡片置顶（突出展示），正文按 `## ` 拆节折叠，引言默认展开，
  "全部展开/全部收起"一键切换；导出仍是完整 Markdown。

### 2.3 精读缓存提速 + 断点修复

- **URL → 正文缓存**（本次运行内 Map）：多方向读到同一 URL 只调一次 Tavily Extract；
- **并行提取**：一次选中的 2 个候选页正文并行拉取（不耗 token），笔记提炼仍串行扣预算；
- **断点顺序修复**：原实现先记"已精读"再提炼笔记，若预算/时间/手动在中间打断，
  续跑会跳过该页 → 笔记永久丢失；现改为**笔记成功写入后才记为已读**，
  被打断的页面续跑时自动补读补齐，不丢内容也不重复。

## 三、自测记录（真实 DeepSeek key）

| 场景 | 结果 |
|---|---|
| 创建定向任务 → 拆解 5 个方向 → 停在待确认 | ✅ `awaiting_confirm`，方向清单完整，tokensUsed=254 |
| 重新拆解 | ✅ 方向全部更新为新方向，费用累加（526） |
| 确认开始 → 研究 60 秒后手动停止 | ✅ running 10 轮搜索 / 18 页精读 / 41k token |
| 停止后组装 | ✅ 报告 12.6k 字、**摘要 329 字**、来源 16 条、正文 6 节 |
| 待确认时取消 | ✅ `cancelled`，无报告，8 秒后确认无组装（前端停止轮询） |
