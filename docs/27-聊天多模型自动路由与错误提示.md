# 阶段 4+：聊天多模型自动路由 + LLM 错误中文提示

> 一句话：聊天不再需要手动切模型——**发图片自动用视觉模型，文字对话继续用文本模型**，
> 两个模型各司其职；LLM 报错也从英文 SDK 错误变成中文可操作提示。

---

## 一、需求来源

| # | 用户要求 | 落地 |
|---|---|---|
| 1 | 发图时报 "Expected content-type to be text/event-stream"（英文） | 根因是上游返回 JSON 错误被 SDK 包装；新增**中文错误翻译**（不支持图片/Key 无效/余额不足/模型名不匹配/限流/超长） |
| 2 | 旧会话切换模型后应生效，不要新开对话 | 会话右上角「模型」下拉切换 → 后端 PATCH sessions/:id/model → 立即生效（原本就有，确认可用） |
| 3 | 不想切换：**同时用两个模型** | **带图自动路由**：发图时若当前模型非视觉，自动改用用户配置里的视觉模型（vision-exp/Qwen3-VL 等），文字对话仍用当前模型 |

## 二、核心设计

### 2.1 带图自动路由（发图用视觉模型，文字用文本模型）

- 视觉模型识别（启发式，前后端一致）：模型名含 `vision / VL / 4V / Omni / GLM-4V` 等关键字；
- 后端 `resolveVisionForUser`：遍历用户全部配置，默认配置优先，返回第一个视觉模型（解密 key）；
- `askAndStream`：带图且当前模型非视觉 → 本次调用改用视觉模型（**不改变会话绑定**）；
- 前端发图时若当前模型非视觉 → toast 提示"图片将自动使用视觉模型 XXX 识别"。

### 2.2 LLM 错误中文翻译

`translateLLMError` 按 HTTP 状态 + 错误文本分派：

| 场景 | 提示 |
|---|---|
| 带图被拒（400/422/not a VLM） | 当前模型不支持图片，请切换到视觉模型或检查模型名 |
| 401 | API Key 无效或已失效，请检查配置 |
| 402 | 账户余额不足，请充值 |
| 429 | 请求过于频繁，稍后再试 |
| Model does not exist | 平台和模型名必须配套（官方 API 与 SiliconFlow 命名不同） |
| context too long | 对话超出上下文长度 |
| 其它 | 带 HTTP 状态码与上游错误信息兜底 |

## 三、自测记录（真实 key）

| 场景 | 结果 |
|---|---|
| 默认=SiliconFlow flash（文本）+ 配置里加 vision-exp | ✅ 日志：`图片路由: deepseek-ai/DeepSeek-V4-Flash → deepseek-v4-flash-vision-exp` |
| 带图消息 | ✅ vision-exp 成功识别回答 |
| 纯文本消息 | ✅ 仍用 flash 文本模型回答 |
| 文本模型发图（无视觉配置） | ✅ 中文提示"当前模型不支持图片…" |
