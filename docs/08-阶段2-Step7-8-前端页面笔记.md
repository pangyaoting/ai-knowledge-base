## 2. 三个前端知识点

### 2.1 FormData 文件上传（axios）

浏览器上传文件必须用 `FormData`：

```ts
export function uploadDocument(knowledgeBaseId: string, file: File) {
  const form = new FormData();
  form.append('file', file); // 字段名必须和后端 FileInterceptor('file') 一致
  return request.post(`/knowledge/${knowledgeBaseId}/documents`, form, {
    timeout: 120_000, // 单独放宽超时
  });
}
```

- **字段名一致**：`append('file', ...)` 对应后端 `@UploadedFile() file`——不一致就收不到文件
- **Content-Type**：axios 检测到 FormData 会自动设置 `multipart/form-data; boundary=...`，不用手动写
- **超时覆盖**：全局 axios 超时 15s，但上传已异步入队立即返回，120s 只是兜底；解析进度由前端轮询文档状态驱动

### 2.2 状态徽章（状态机的 UI 呈现）

后端文档状态 `pending / processing / done / failed`，替换场景还有 **`replacing`（替换中）**：同名文件重新上传时旧文档先被标记为 replacing，新文档处理成功后才删除旧版——前端映射成不同颜色的徽章：

```ts
const statusText = { pending: '排队中', processing: '解析中', replacing: '替换中', done: '已完成', failed: '失败' };
// done → 绿、failed → 红、processing/pending → 黄（带脉冲动画）
```

**前端只是"展示"状态，状态由后端驱动**——这是状态机模式的分工。

### 2.3 类型共享的体现

`types/knowledge.ts` 的接口和后端 Prisma 模型字段一一对应（`_count` 对应 Prisma 的 include 统计）：

```ts
export interface KnowledgeBase {
  id: string;
  name: string;
  ...
  _count?: { documents: number }; // 后端 findMany include _count 的结果
}
```

**这就是 monorepo 前后端共享类型的价值**（阶段 0 搭的 `packages/shared` 也可以放类型，当前先放在前端 types 里，后续可迁移）。
