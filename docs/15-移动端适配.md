# 阶段 4+：移动端适配

> 一句话：手机打开也能用——导航有入口、会话列表可滑出、表格不挤爆。
> 原则：**不重写移动版，用 Tailwind 响应式类让同一套代码自适应**（375px ~ 1440px）。

---

## 一、大白话：改了什么

桌面版是"宽屏 + 侧边栏"布局，手机屏幕窄，直接照搬会：找不到导航、会话列表占掉一半屏、表格被挤变形。这轮做四件事：

1. **导航入口**：顶栏在小屏显示汉堡按钮，点开下拉面板选「知识库 / 对话 / 数据看板」；
2. **会话列表**：对话页左侧列表在手机默认收起，头部汉堡点开从左边滑出（带遮罩，点遮罩关闭）；
3. **表格**：文档列表表格在窄屏变成"容器内横向滚动"，整页不被撑破；
4. **图表**：数据看板本就有 `window.resize` 监听，图表随容器自动重绘。

## 二、实现要点（都是响应式类的组合）

| 问题 | 方案 |
|------|------|
| 导航在 <640px 消失 | 汉堡按钮 `md:hidden` + 下拉面板 `md:hidden`；`watch(route)` 收起 |
| Chat 侧栏占宽 | `absolute -translate-x-full md:static md:translate-x-0` + `sidebarOpen` 状态切换；遮罩 `md:hidden` |
| 表格挤爆页面 | 容器 `overflow-x-auto` + 表格 `min-w-[760px]`，滚动被限制在容器内 |
| 视口 | `index.html` 已有 `<meta name="viewport">` |

**关键细节**：`-translate-x-full`（基础类）与 `md:translate-x-0`（响应式类）共存时，Tailwind 生成 CSS 中响应式类靠后，桌面端永远优先显示——同一个 `aside` 标签，手机是抽屉、桌面是常驻栏，零 JS 分支。

## 三、面试话术

- "没有做第二套移动页面，全靠响应式断点（sm/md/lg）一套代码自适应，维护成本最低。"
- "会话列表用 translate 过渡做抽屉，桌面端 `md:static` 还原常驻，移动体验和桌面体验互不牺牲。"
- "表格在移动端是容器内横向滚动而非整页溢出——滚动范围可控，这是移动适配最容易踩的坑。"
