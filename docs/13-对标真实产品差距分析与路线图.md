# 阶段 4+：对标真实上市级产品 —— 差距分析与路线图

> 目标：不是"能演示的课程设计"，而是**真实用户愿意用、能上线获客**的产品。
> 对标对象：Dify、MaxKB、RAGFlow、Coze、Notion AI、ChatPDF 等真实产品（[选型对比参考](https://cloud.baidu.com/article/3661215)、[RAGFlow/Dify 知识库对比](https://blog.csdn.net/xiaocheng121212/article/details/154575955)、[生产级 RAG 平台参考](https://github.com/ishani1813/DocuMind-AI-Document-Intelligence-Platform)）。

## 一、现状盘点（已经具备的"上市级"能力）

| 能力 | 说明 |
|------|------|
| 混合检索 | 向量 + pg_trgm 关键词 + RRF 融合 + 相似度阈值（超过多数同类产品默认配置） |

| 数据看板 | 真实 Token 用量（include_usage）、7 日趋势、Top 知识库 |
| 工程化 | SSE 流式、Markdown+代码高亮、JWT 双 token、限流、CI/CD、docker |

## 二、差距分析（按"真实用户会不会用"排序）

### P0 —— 没有它，用户会觉得"这不是个完整产品"

| # | 差距 | 真实产品做法 | 我们做 | 面试价值 |
|---|------|------------|--------|---------|
| 1 | **多轮查询改写**（指代消解）：第二问"它的原理是什么"，检索却拿着"它"去搜 | Dify 有 query rewriting：先让 LLM 把问题改写为独立完整问法再检索 | 有历史时先改写（只影响检索，回答仍用原问题） | "两阶段：改写→检索→生成" |
| 2 | **异步任务队列**：20MB PDF 同步处理卡十几秒，大文件多时接口超时 | 任务队列 + 进度轮询（Dify/所有平台） | 内存队列 + 文档状态轮询（阶段 4+ 最大工程项） | "异步化"是架构分水岭 |
| 3 | **个人中心**：不能改昵称/密码 | 所有产品标配 | 设置页（资料 + 改密码） | 用户体系完整性 |
| 4 | **会话导出**：回答没法带走 | 导出 Markdown/复制 | 会话导出 .md | 数据可携带（GDPR 思维） |
| 5 | **空状态引导**：新用户不知道干嘛 | 首次引导 + 一键示例数据 | 空状态提示 + 示例知识库一键导入 | 产品思维 |

### P1 —— 体验质变（上市后的口碑分水岭）

## 三、执行顺序（按 P0 → P1 → P2）

1. ✅ 多轮查询改写（有历史时 LLM 改写→检索，回答仍用原问题；改写失败回退不阻塞）
2. ✅ 会话导出 Markdown（含引用来源，`GET /chat/sessions/:id/export` + 对话区头部导出按钮，会话列表不重复放导出入口）
3. ✅ 个人中心（`/settings`：改昵称 + 改密码，旧密码校验）
4. ✅ **空状态引导 + 示例数据一键导入**：知识库空态三步引导（创建→上传→提问）+「一键导入示例数据」（`POST /demo/seed` 幂等：创建"示例知识库"+3 篇示例文档，走真实队列管线异步向量化，新用户 6 秒即可体验完整流程）
5. ✅ **异步任务队列（BullMQ + Redis）**：上传=校验+存盘+入队，**接口秒回（72ms）**；worker 后台解析/分块/向量化（并发 2、失败指数退避重试 3 次、Redis 持久化）；失败保留 `Document(failed)` + 原因（可重传）；前端轮询状态流转（排队中→解析中→已完成）；同名替换在任务成功后才删旧版
6. ✅ **纯对话模式（知识库可不选）**：会话问答范围三态（不使用/全部/指定），选择器 radio 切换、指定模式空勾选禁止提交；不选知识库时后端跳过检索与查询改写，纯 LLM 对话（省一次改写调用）；系统提示词按模式切换，导出 Markdown 标注"纯对话"
7. ✅ Reranker 两阶段检索（召回 Top-N → bge-reranker 精排 → Top-K；失败自动回退 RRF）
8. ⏳ 文档预览 + 引用定位 → 移动端 → 搜索 → 骨架屏
9. ⏳ 2FA → 配额 → 备份 → 暗色
10. ⏳ 部署上线

> 原则：每一项都"先方案后实现"，可量化（如"改写后指代问题命中率提升"），文档同步沉淀。
