## 二、知识地图：先建立全局观

这是一个**文档问答（RAG）全栈应用**。所有功能围绕一条主线展开：

```
                    ┌─────────────────────────────────────────┐
                    │              用户（浏览器）               │
                    └───────────────┬─────────────────────────┘
                                    │
              ┌─────────────────────┼─────────────────────┐
              ▼                     ▼                     ▼
      【知识库】上传文档     【对话】问问题      【研究报告/Agent】丢主题
              │                     │                     │
        解析→分块→向量化       混合检索+RAG生成       拆解→检索→撰写→汇总
              │                     │                     │
              └──────────┬──────────┘                     │
                         ▼                                │
              PostgreSQL (pgvector) ◄──────────── 长期任务队列 (BullMQ)
              Redis (会话/队列/验证码)                     │
              ┌────────────────────────────────────────────┘
              ▼
      大模型 API（用户自带 Key = BYO）
```

**六个必须理解的核心概念**（全书会逐个展开）：

| # | 概念 | 一句话 | 所在章节 |
|---|---|---|---|
| 1 | **分块 (Chunking)** | 长文档切成小块，检索才有"准头" | 03 |
| 2 | **向量化 (Embedding)** | 把文本变成高维向量，语义相似 ≈ 距离近 | 03 |
| 3 | **混合检索 (Hybrid Search)** | 向量(语义)+关键词(字面)两路找，按排名融合 | 04 |
| 4 | **重排+门控 (Rerank & Gate)** | 粗召回后精排，质量不够宁可不说 | 04 |
| 5 | **异步队列 (BullMQ)** | 长任务丢后台跑，接口秒回 | 06 |
| 6 | **自带 Key (BYO)** | 用户用自己的模型 Key，平台零对话成本 | 07 |

## 四、快问快答（先给你几个"钩子"）

**Q：为什么文档要先"分块"再检索？**
A：整篇文档塞给模型太长太贵，且"哪段跟问题相关"无从定位。切成 500 字左右的小块，检索时按块找相似度，命中哪块就把哪块（连同它的上下文）喂给模型——这就是 RAG 能"带来源回答"的根基。详见 03。

**Q：这个项目跟普通 ChatBot 有什么本质区别？**
A：普通 ChatBot 只靠模型自身知识；本项目多了一条**知识库检索链**：回答前先在你的文档里检索相关内容，模型"看着资料回答"，并且每条回答标注 `[来源N]`，点击能跳回原文段落。详见 04。

**Q：为什么研究报告/Agent 用"队列"而不是直接生成？**
A：一份报告要拆 3~5 个子问题、每个都要检索+调模型，耗时几分钟。如果请求线程同步等它，用户浏览器会一直转圈、服务器线程被占死。用 BullMQ 把任务丢给后台 worker，接口立刻返回"排队中"，前端轮询进度。详见 06。

## 六、开始之前：把项目跑起来

后面每章都假设你能在**本机运行**项目。还没有跑起来的话，先按 `docs/部署运维/02-部署上线指南.md`（或仓库 README）完成：

```bash
# 环境：Node 22+、pnpm 11、PostgreSQL 16(+pgvector)、Redis 7
git clone <你的仓库> && cd ai-knowledge-base
pnpm install
# 配置 apps/server/.env（参考 apps/server/.env.example）
pnpm --filter @app/server prisma:migrate   # 建表
pnpm --filter @app/server start:dev        # 后端 3000
pnpm --filter @app/web dev                 # 前端 5173
```

注册一个账号 → 在「模型配置」绑定你自己的 DeepSeek Key → 上传几篇文档 → 随便问一句。跑通了，翻到 [01](01-项目骨架与总体架构.md)。
