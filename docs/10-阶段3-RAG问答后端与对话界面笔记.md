## 1. 后端：RAG 问答编排（chat.service.ts）

```
提问 → ①校验会话归属 → ②检索 Top-K（rag.service）→ ③存用户消息
     → ④取历史对话 → ⑤组装 Prompt → ⑥DeepSeek 流式 → ⑦逐字转发 SSE
     → ⑧落库助手消息+引用 → ⑨首问自动生成标题
```

### 1.1 检索（rag.service.ts）

```sql
SELECT c.content, d.filename, 1 - (c.embedding <=> '[问题向量]'::vector) AS similarity
FROM chunks c JOIN documents d ON d.id = c.document_id
WHERE c.embedding IS NOT NULL
  AND d.knowledge_base_id = ?   -- 会话绑定了知识库时过滤
ORDER BY c.embedding <=> '[问题向量]'::vector
LIMIT 5
```

关键点：
- **动态 WHERE**：用 `Prisma.sql` 片段拼接可选条件，参数仍然绑定（防注入）
- 问题向量用**同一个 bge-m3** 向量化（和入库模型一致，语义空间才对得上）

### 1.2 Prompt 组装（面试深挖点）

```text
【系统提示词】
你是一个严谨的 AI 知识库问答助手。请仅根据提供的【参考资料】回答用户问题。
如果参考资料中没有相关信息，请明确说明"资料库中未找到相关内容"，不要编造。
回答中引用资料时请标注 [来源1]、[来源2] 等编号。

【参考资料】
[1]（来自文档《Vue3核心知识整理》第 1 段）
Vue3 的响应式系统基于 ES6 的 Proxy 实现...

【历史对话】（最近 3 轮）
用户：...
助手：...

【用户问题】
Vue3 的响应式系统相比 Vue2 有什么优势？
```

- **抑制幻觉**："资料里没有就说没有，不要编造"——RAG 的立身之本
- **引用编号**：资料带 [N]，模型回答时标注 → 前端解析出"来源"（实测回答里出现了 "[来源1]"，链路成立）
- **历史滑动窗口**：`HISTORY_ROUNDS = 6`（最近 3 轮），控制 token 成本

### 1.3 SSE 输出与拦截器的配合（踩过的设计点）

- 控制器用 `@Res() res` 手动管理响应：设置 `text/event-stream` 头 → `flushHeaders()` → 逐条 `res.write('data: ...\n\n')`
- **全局 TransformInterceptor 会包装所有返回值** → 加 `headersSent` 判断：响应已开始就跳过包装（否则 SSE 流会被包成 JSON）
- **先校验后流式**：会话归属校验在 flushHeaders **之前**（出错时全局过滤器还能正常返回 JSON 404）；进入流式后才 try/catch 发 error 事件

### 1.4 中止生成（不浪费 token）

```ts
const abortController = new AbortController();
res.on('close', () => abortController.abort());  // 客户端断开
// openai SDK 的 signal 放第二个参数（options），不是 body 里
const stream = await client.chat.completions.create({...}, { signal: abortController.signal });
```

用户点"停止" → fetch 中止 → 后端收到 close → abort DeepSeek 流 → for-await 抛 AbortError → 静默返回（不写 error 事件）。

**注意踩坑**：openai SDK 的 `signal` 参数在 `create(body, { signal })` 的**第二个参数**，一开始放 body 里 TS 直接报错。

## 2. 前端：对话界面（Chat.vue）

### 2.1 为什么不能用原生 EventSource

原生 `EventSource` 只支持 **GET** 请求——无法带请求体，也无法自定义 Authorization 头（只能 URL 参数带 token，会留在历史记录里）。

方案对比：

| 方案 | POST+Header | 中止 | 断线重连 | 复杂度 |
|------|------------|------|---------|--------|
| 原生 EventSource | ❌ 只支持 GET | 可 | 自动 | 低 |
| **fetch-event-source**（本项目） | ✅ | ✅ AbortController | 自动（可关闭） | 低 |
| 手写 fetch + ReadableStream | ✅ | ✅ | 自己写 | 高 |

### 2.2 流式渲染的状态管理

```
提问 → 用户消息立即上屏（乐观渲染）
     → 助手消息占位（streamContent = ''）
     → onDelta 事件逐字累加 → v-html 实时重渲染
     → onDone → 把完整消息并入 messages 列表（刷新后从数据库恢复）
```

- 流式中的消息**不落库**（避免每字一次 IO），完成后才存
- 自动滚动：watch `messages + streamContent` → `nextTick` → scrollTop 到底

### 2.3 Markdown 渲染 + 代码高亮 + 复制（markdown.ts）

- `markdown-it`：表格/列表/引用等标准语法
- `highlight.js`：代码高亮
- 复制按钮：渲染后给每个代码块包一层容器 + 按钮，页面用**事件委托**处理点击（不用给每个按钮绑监听）

### 2.4 引用溯源 UI

每个助手消息下方"引用来源"折叠区：`来源N` 徽章 + 文件名 + 相似度 + 内容预览。**回答了"AI 凭什么这么答"的问题**。

## 3. 性能优化（简历量化素材）

**问题**：Chat 页面打包体积 1054 kB（gzip 367 kB）——因为 `highlight.js` 默认全量引入所有 190+ 种语言。

**优化**：改为 `highlight.js/lib/core` + 只注册常用语言（js/ts/py/bash/json/html/css/sql）。

**结果**：Chat chunk **1054 kB → 170 kB（gzip 367 → 72 kB），-84%**。

**简历写法**："首屏 JS 通过 highlight.js 按需注册语言包，对话页 chunk 从 1054 kB 降至 170 kB（gzip 367→72 kB）"。

## 4. 本阶段踩的坑

| 坑 | 解决 |
|----|------|
| openai SDK `signal` 参数位置 | 在 `create(body, { signal })` 第二个参数 |
| Prisma CLI 找不到 DATABASE_URL | 它只从当前目录读 .env → 配置统一在**根目录 `.env`**，migrate 在根目录跑（`npx prisma migrate dev --schema apps/server/prisma/schema.prisma`），generate 无需环境仍在 apps/server 跑 |
| SSE 被全局拦截器包装 | 拦截器加 `headersSent` 判断跳过 |
| SSE 返回 201 | NestJS POST 默认 201 → `@HttpCode(200)` 修正 |
| 检索结果顺序 | openai embeddings 返回顺序不保证 → 按 `index` 排序 |
| 前端 chunk 过大 | highlight.js 按需引入 |
