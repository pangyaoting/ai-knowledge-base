# 36 · 项目学习指南：由浅入深吃透这个 AI 知识库（自学路线）

> 一句话：这不是"项目说明书"，而是一张**学习地图**——按由浅到深 8 个阶段，
> 从"把项目跑起来"到"读懂每个核心文件"再到"动手改造"，每个阶段都有：
> **目标 → 知识点 → 代码在哪 → 动手任务 → 自测**。
> 学完 = 能独立复刻 + 面试讲得清 + 证明项目"实用"。

## 一、先回答"这个项目实不实用"

把项目放知识库里学，第一件事是确认它值得学、学完有用。

**痛点 → 方案对照（面试/答辩就这么讲）：**

| 真实痛点 | 本项目的解法 |
|---|---|
| 公司/团队文档散乱，用关键词搜不到 | 上传即自动解析分块 + 向量化，语义检索（搜"图片识别"能命中"图像分类"） |
| 问 AI 没有依据，答错也没处查 | RAG：回答基于知识库、每条引用标注来源，点击可跳到原文位置 |
| 资料库没内容时 AI 瞎编 | 相关性门控 + 无资料兜底：够不着就明说"未检索到知识库资料" |
| 长报告人工写要几小时 | 自主研究 Agent：限时限量自动拆解方向、查资料、分节撰写、断点续跑 |
| 大模型 API 成本不可控 | 强制用户自带 Key（BYO）+ 用量看板统计 Token 消耗 |
| 普通笔记软件不检索代码 | 支持代码文件入库、按代码语义分块、检索时知道片段来自哪个文件 |

**"狗粮法"（最实用的一招）：** 把这个项目自己的 `docs/` 目录上传进知识库，然后用问答检验——
问"RRF 融合是怎么实现的？""部署需要哪些步骤？"它都能带来源回答。**项目能学自己的文档 = 实用性最直接的证据**，面试现场演示这一下就够。

## 三、阶段 0：把项目跑起来（半天~1 天）

**目标：** 本机完整跑通，看到它真的能用。

**知识点：** monorepo（pnpm workspace）、环境变量、数据库迁移、双服务启动。

**步骤：**
1. 装环境：Node 24、pnpm 11、PostgreSQL 16（+pgvector 扩展）、Redis 7、Docker（WSL2 内）；
2. `git clone` 项目 → `pnpm install`；
3. 按 `docs/02-部署上线指南.md` 配 `.env`（数据库/Redis/模型 Key）；
4. `pnpm prisma:migrate` 建表 → 起后端（3000）→ 起前端（5173）；
5. 注册账号 → 「模型配置」绑定你自己的 DeepSeek/硅基流动 Key → 上传几个文档 → 提问。

**动手任务：** 把前端端口改成 5174（`vite.config.ts`），把首页欢迎语改一句你自己的话。

**自测：** 能登录；上传 md/txt 后状态变"已完成"；提问回答带来源；暗色/浅色模式切换正常。

**坑：** Windows 上 `ps1` 脚本可能被 ExecutionPolicy 挡，一律用 `.cmd`；vite 改文件后 watcher 可能因临时文件冲突崩溃，重启即可。

## 四、阶段 1：认证与后端骨架（2~3 天）

**目标：** 看懂 NestJS 怎么组织模块，认证怎么做的。

**知识点：** NestJS 模块/控制器/服务分层、Prisma ORM、JWT 双 Token（access 15min + refresh 7d）、Redis 轮换、bcryptjs 加密、邮箱验证码（6 位/10 分钟/60 秒重发/消费即删）。

**代码在哪：** `apps/server/src/modules/auth/`、`email-code/`、`common/`（守卫/装饰器/拦截器）、`prisma/schema.prisma`。

**面试问题（阶段末要能答）：**
- 为什么 accessToken 短、refreshToken 长？→ 泄漏窗口小；refresh 走 Redis 可撤销。
- 为什么用邮箱验证码而不是 2FA？→ 用户反馈验证器繁琐，验证码覆盖注册/忘记密码/换绑，体验简单（这是个"取舍"故事，面试加分）。
- 全局 JWT 守卫怎么放行登录接口？→ `@Public()` 装饰器。

**动手任务：** 给用户加一个"修改昵称"的 `PATCH /api/user/profile` 接口（控制器+服务+DTO+前端调用）。

**自测：** 写接口后用 curl/前端调用成功；错误密码返回 401；验证码错误返回 400。

## 五、阶段 2：知识库——上传、解析、向量化（3~5 天，核心）

**目标：** 讲清"文档是怎么变成可检索向量的"。

**知识点：**
- 上传链路：Multer（内存存储）→ `detectFileType` 分类（文本/代码/PDF/Word/附件）→ 入库即返回，**异步解析**；
- BullMQ 队列：上传秒回，worker 后台解析（并发 2、失败重试 3 次指数退避）；
- 分块 `text-splitter.ts`：递归切块（默认 500 字/重叠 100），优先级 `段落→句号→逗号→空格`，重叠尾巴不丢边界词；代码按行切、超长单行硬切；
- Embedding：bge-m3（1024 维），批量 10 + 指数退避，写入 PostgreSQL **pgvector**（HNSW 余弦索引）；
- 增量向量化：`contentHash` SHA-256 去重，同名同内容直接跳过（省 API 钱）。

**代码在哪：** `knowledge/`、`document-queue.service.ts`、`document-processor.service.ts`、`knowledge/utils/text-splitter.ts`、`embedding.service.ts`。

**面试问题：**
- 为什么分块？块太大/太小各有什么问题？
- 重叠（overlap）有什么用？→ 切在句子中间时上下文不丢。
- 为什么上传要异步？→ 大文档解析可能几十秒，同步会超时，队列让接口秒回。

**动手任务：** 把 `text-splitter` 的 chunkSize 改成 300，重新上传一个长文档，对比检索效果；再改回 500。

**自测：** 上传含代码的文档（如本项目一个 `.ts` 文件），问"这个文件里 XX 函数怎么写的"，能带文件路径来源回答。

## 六、阶段 3：RAG 对话——检索、重排、生成（3~5 天，核心）

**目标：** 讲清"从问题到带来源的回答"完整链路。

**知识点：**
- SSE 流式：`@Res()` + `flushHeaders()`，事件协议 `sources/delta/done/error`，前端 `fetch-event-source`；
- 混合检索：向量检索 + **pg_trgm** 关键词检索 → **RRF 融合**（`rrf.ts`，`1/(60+rank)`，两路各 Top-15 合并取 Top-5）；
- 重排：bge-reranker 交叉编码器对 Top-15 精排 → 相关性门控 `RERANK_MIN_SCORE=0.1`（够不着就不给答案）；
- 查询改写：多轮对话先做指代消解（"它"→上一轮实体）；
- 无资料兜底：检索为空允许模型用自身知识，但必须披露"（未检索到知识库资料…）"；
- 联网：Tavily 搜索，回答分知识库/网络双来源。

**代码在哪：** `chat/rag.service.ts`、`chat/rrf.ts`、`chat/chat.service.ts`、`rerank.service.ts`。

**面试问题（必背）：**
- RRF 为什么只依赖排名不依赖分数？→ 两种检索的分数不可比（余弦 vs 词频），排名融合鲁棒。
- 为什么召回 15 条再重排取 5 条？→ 两阶段精排：粗召回（快）+ 交叉编码器精排（贵），性价比最高。
- 门控是干什么的？→ 检索质量不够时宁可拒绝，不喂错误上下文。

**动手任务：** 把 `.env` 的 `RERANK_MIN_SCORE` 从 0.1 调到 0.5，问一个冷门问题看它怎么变（回答被拒/只说自身知识）；再调回 0.1。

**自测：** 能讲出"问题→改写→双路检索→RRF→重排→门控→生成→来源"每一步在哪个文件、参数是多少。

## 十一、高效学习方法论（怎么学得又快又牢）

1. **顺序读代码：入口 → 控制器 → 服务 → 工具**。每个功能先找路由（controller），再进服务，最后看工具函数；
2. **"改一处，看效果"**：不要光读，改参数/加日志/换文案，立刻看到变化——比读十遍记得牢；
3. **狗粮法**：把 docs/ 传进知识库，用问答学自己的项目（同时验证检索质量）；
4. **输出倒逼输入**：每学完一阶段，假装给同学讲一遍（或写成小笔记）；
5. **面试驱动**：每个模块先看"面试问题"再回头学，学完能答就过关；
6. **不会的别硬啃**：Canvas 粒子引擎、Reranker 原理这类，知道"是什么、为什么、在哪"即可，不要求手写。
