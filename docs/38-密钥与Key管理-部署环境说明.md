# 38 · 密钥与 Key 全景 + 部署环境说明（谁花钱、谁持有、放哪里）

> 一句话：项目上线后同时存在「花钱的模型 Key」「登录用的凭据」「CI 用的公钥私钥」几套东西，
> 很容易混。这篇把它们全部列清：**每把 Key 是干什么的、花不花钱、放哪、怎么配**，
> 并解释「为什么部署后上传文件变快了」。

---

## 一、为什么要先讲"Key 分两类"

| 类别 | 是什么 | 例子 | 会不会花钱 |
|---|---|---|---|
| **模型 API Key** | 调大模型/向量化接口的凭证，**按调用量计费** | DeepSeek、硅基流动、Tavily | ✅ 会花钱 |
| **环境凭据** | 登录/加密/部署用的密钥，**不按量计费** | root 密码、CI 私钥、JWT_SECRET、邮箱授权码 | ❌ 免费 |

**最容易搞混的**：DeepSeek 的 `sk-` Key（花钱）和 CI 部署的 `SSH 私钥`（免费，只是登录凭证）——一个是"买服务"，一个是"开门锁"。

## 二、花钱的 Key 清单（按用量排）

| Key | 干什么 | 花不花钱 / 多少 | 放哪 | 必须吗 |
|---|---|---|---|---|
| **DeepSeek API Key** | 对话 / 研究报告 / 自主研究 Agent 的主模型 | ✅ 按 token 计费（对话一次几分~几毛） | **用户网页端「模型配置」绑定**（加密存库，BYO 设计） | 必须（AI 对话全靠它） |
| **硅基流动 API Key** | ① Embedding 向量化（bge-m3）② Rerank 重排（bge-reranker） | ✅ 按 token 计费；**上传文档向量化的大头**（每次入库都消耗） | **服务器 `.env`**（`SILICONFLOW_API_KEY`） | 必须（文档无法向量化就检索不了） |
| **Tavily API Key** | 联网搜索（提问带"联网搜索"时） | ✅ 有免费额度，超了收费 | 服务器 `.env`（`TAVILY_API_KEY`） | 可选（联网是加分功能） |
| **QQ 邮箱 SMTP 授权码** | 注册/忘记密码发验证码邮件 | ❌ 免费 | 服务器 `.env`（`MAIL_PASS`） | 可选（不配则开发模式回显验证码） |
| **腾讯云服务器** | 跑整套服务 | ✅ 157 元/年（新用户） | — | 必须 |

**费用真相（面试/自己心里要有数）**：
- **对话**：用户自带 Key，用户买单（这是 BYO 设计的意义，平台零对话成本）；
- **Embedding/重排**：平台/你买单（硅基流动），但很便宜——bge-m3 每千 token 约几分钱，一份文档几 KB 文本向量化成本可忽略；
- **所以一个"自用演示"场景，每月开销可能不到 10 元**（主要是对话 token，自己用省着点）。

## 三、凭据体系（免费但容易乱：密码 / 公钥私钥）

### 3.1 三把"钥匙"的角色

| 凭据 | 谁→谁 | 干什么 | 存放位置 |
|---|---|---|---|
| **root 密码** | 你 → 服务器 | 腾讯云网页终端 / SSH 密码登录 | 你脑内（建议改强！） |
| **kb_ci 私钥** | GitHub Actions → 服务器 | CI 自动部署时 SSH 登录服务器 | **GitHub Secrets**（`SSH_PRIVATE_KEY`） |
| **kb_ci 公钥** | 服务器侧 | 服务器"认识"这把私钥（白名单） | 服务器 `~/.ssh/authorized_keys` |
| **kb_deploy 密钥对** | （旧）服务器 → GitHub | 早期为服务器 clone GitHub 准备的部署密钥 | 本地 `~/.ssh/kb_deploy`（现已被 tar 下载替代，可弃用） |

### 3.2 公钥/私钥一句话理解

- **私钥** = 钥匙（自己留着，绝不外传）；**公钥** = 锁（交给对方）；
- CI 部署流程：GitHub 拿**私钥**去开锁，服务器用**公钥**验证 → 配对成功才放行登录；
- 你本地 `C:\Users\qie'li\.ssh\` 下现在有：
  - `kb_ci` / `kb_ci.pub` —— CI 自动部署用（私钥在 GitHub Secrets）
  - `kb_deploy` / `kb_deploy.pub` —— 早期方案遗留，已不需要（别删也行，别外传）

### 3.3 服务器 .env 里的随机密钥（别改，改了要连带）

| 变量 | 干什么 | 备注 |
|---|---|---|
| `JWT_SECRET` / `JWT_REFRESH_SECRET` | 签发访问令牌/刷新令牌的签名 | 改了所有人要重新登录 |
| `MODEL_KEY_SECRET` | 加密用户网页绑定的模型 Key（AES-256-GCM） | **改了用户存的 Key 全解不开**（需重绑） |
| `DATABASE_URL` 密码 | PostgreSQL（docker 内 kb123456） | 容器参数对应 |
| 服务器 `.env` 备份 | `/opt/kb/.env.bak` | 每次 CI 部署自动备份 |

## 四、为什么部署后"上传文件变快了"

**结论：上传本来就不慢——"快"是异步架构 + 环境差异，不是部署做了什么魔法。**

### 4.1 上传接口天生秒回（本地和服务器一样）

```
你点上传 → 后端：校验文件 → 存盘 → 建记录(pending) → 丢进 BullMQ 队列 → 立即返回（<1秒）
                                     ↑
                    真正的解析/分块/向量化在后台 worker 跑，前端轮询进度
```
（代码：`documents.service.ts` 注释"入队并立即返回（接口响应 <1s）"，`document-queue.service.ts`）

所以"点上传立刻有反应"是**设计使然**，本地部署都这样。

### 4.2 那为什么感觉本地慢、部署快？真实原因

1. **开发模式 vs 生产模式（最大因素）**：
   - 本地用 `npm run start:dev`（ts-node watch）——**每个请求都要经过 TS 即时编译/热重载**，后端处理开销大；
   - 服务器用 `pm2` 跑 `nest build` 后的**纯编译 JS**——无编译开销，快一个量级；
2. **本地机器资源被抢占**：本地同时跑 vite（前端 dev 服务器，还要实时编译 .vue）+ 后端 watch + 浏览器 + 编辑器，解析队列 worker 抢不到 CPU；
3. **本地数据库环境慢**：如果本地 PG/Redis 跑在 WSL2 或旧硬盘上，磁盘 IO 慢会拖解析；
4. **服务器环境干净**：2C4G 独享 + SSD，PG/Redis/Node 都是容器轻量跑，解析并发 2，全流程顺畅。

### 4.3 一个"看起来更快"的细节

前端"上传中/解析中"环形进度靠**轮询文档状态**驱动——服务器解析快，状态流转快，进度条转得快，体感就更快。

## 五、安全清单（当前状态 + 建议）

| 项 | 状态 | 建议 |
|---|---|---|
| root 密码 | ⚠️ 较弱（`123456@qwe`） | **改强**：腾讯云控制台重置密码（10 位+大小写数字符号） |
| kb_ci 私钥 | 只在 GitHub Secrets | ✅ 正确；本地 `kb_ci` 文件别外发 |
| 模型 Key | 用户侧加密存库；平台 Key 在服务器 .env | ✅ 仓库里绝不能出现任何 `sk-` |
| 服务器 .env | `/opt/kb/ai-knowledge-base/.env`（CI 自动备份到 /opt/kb/.env.bak） | ✅ |
| 防火墙 | 只开 22/80/443（nginx 反向代理，3000 不对外） | ✅ |
| HTTPS | 未配（IP+HTTP，"不安全"提示） | 可选：域名+备案+Let's Encrypt |

## 六、一句话总结（面试/复盘用）

"项目有两条线：**花钱的是模型 API**（对话走用户 BYO Key 用户买单，平台仅 Embedding/重排用硅基流动，自用月成本不到 10 元）；**免费的是凭据**（root 密码、CI 公钥私钥配对、JWT/加密密钥）。部署后上传变快不是魔法——上传接口本来就异步秒回，真正差异是生产编译 JS 无开发期 TS 编译开销 + 服务器环境干净。"
