## 二、最终架构（跑在 159.75.52.172）

```
用户浏览器
    │ http://IP
    ▼
nginx (80)  ── gzip 压缩静态资源
    │ /api → 反代 127.0.0.1:3000（SSE 关缓冲）
    │ /assets → 前端 dist（30d 缓存）
    │ /avatars → uploads/avatars（no-store）
    ▼
pm2: kb-server (NestJS 编译产物 dist/main.js, 端口 3000)
    ├─ PostgreSQL 16（docker: pgvector/pgvector:pg16, 端口 5432）
    ├─ Redis 7（docker, 端口 6379）
    └─ BullMQ 队列（上传解析 / 报告 / Agent 后台任务）
```

关键路径：代码 `/opt/kb/ai-knowledge-base`、数据卷 `/opt/kb/data/pg`、头像 `uploads/avatars/`。

## 三、每步真实命令（可复现）

### 3.1 系统初始化（Ubuntu 22.04, root）

```bash
# apt 换阿里源
sed -i 's|http://archive.ubuntu.com/ubuntu|http://mirrors.aliyun.com/ubuntu|g; s|http://security.ubuntu.com/ubuntu|http://mirrors.aliyun.com/ubuntu|g' /etc/apt/sources.list
apt update && apt upgrade -y
# 2G swap（4G 内存跑全套更稳）
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
timedatectl set-timezone Asia/Shanghai
ufw allow 22/tcp; ufw allow 80/tcp; ufw allow 443/tcp; ufw --force enable
```

### 3.2 环境（国内源）

```bash
# Docker（阿里云源）+ 腾讯加速
curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg | gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://mirrors.aliyun.com/docker-ce/linux/ubuntu $(lsb_release -cs) stable" > /etc/apt/sources.list.d/docker.list
apt update && apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin nginx
echo '{ "registry-mirrors": ["https://mirror.ccs.tencentyun.com"] }' > /etc/docker/daemon.json
systemctl restart docker
# Node 22 + pnpm 11（npmmirror）
curl -fsSL https://npmmirror.com/mirrors/node/v22.14.0/node-v22.14.0-linux-x64.tar.xz -o /tmp/node.tar.xz
tar -xJf /tmp/node.tar.xz -C /usr/local/nodejs --strip-components=1
ln -sf /usr/local/nodejs/bin/{node,npm,npx} /usr/local/bin/
npm config set registry https://registry.npmmirror.com
npm install -g pnpm@11 && pnpm config set registry https://registry.npmmirror.com
```

### 3.3 数据库容器（关键：**pgvector 镜像**）

```bash
docker run -d --name kb-postgres --restart=always \
  -e POSTGRES_USER=kb -e POSTGRES_PASSWORD=kb123456 -e POSTGRES_DB=kb \
  -v /opt/kb/data/pg:/var/lib/postgresql/data -p 5432:5432 pgvector/pgvector:pg16
docker run -d --name kb-redis --restart=always -p 6379:6379 redis:7
docker exec kb-postgres psql -U kb -d kb -c "CREATE EXTENSION IF NOT EXISTS vector;"
```

### 3.4 代码（GitHub 加速下载，非 git clone）

```bash
cd /opt/kb
wget -O /tmp/kb.tar.gz "https://ghfast.top/https://github.com/pangyaoting/ai-knowledge-base/archive/refs/heads/main.tar.gz"
tar -xzf /tmp/kb.tar.gz -C /opt/kb && mv ai-knowledge-base-main ai-knowledge-base
```

### 3.5 迁移 / 构建 / 启动

```bash
cd /opt/kb/ai-knowledge-base
pnpm install --no-frozen-lockfile
npx prisma migrate deploy --schema apps/server/prisma/schema.prisma
pnpm --filter @app/server build
pnpm --filter @app/web build
export PATH="$PATH:$(npm prefix -g)/bin"
pm2 start apps/server/dist/main.js --name kb-server && pm2 save
```

## 四、踩过的坑（每个都真实发生，按严重度）

| 坑 | 现象 | 根因 | 解决 |
|---|---|---|---|
| **pgvector 扩展缺失** | 迁移报 `extension "vector" is not available` | postgres:16 官方镜像**不带 pgvector** | 换 `pgvector/pgvector:pg16` 镜像重建容器，`CREATE EXTENSION vector` |
| **迁移 SQL BOM** | `syntax error at or near "\u{feff}"` | Windows 生成 migration.sql 带 UTF-8 BOM | `sed -i '1s/^\xEF\xBB\xBF//' migration.sql` + `prisma migrate resolve --rolled-back` 重跑 |
| **迁移失败卡住** | `P3009 found failed migrations` | 首次失败记录留在 `_prisma_migrations` | `prisma migrate resolve --rolled-back <name>` 标记回滚再 deploy |
| **GitHub 直连断** | `GnuTLS recv error` / clone 失败 | 大陆服务器到 GitHub 链路不稳 | 走加速代理下载 tar（ghfast.top / ghproxy.net） |
| **tar 部署无 .git** | `git pull: not a git repository` | 加速下载解压的代码没有 .git 目录 | 每次更新 = 重新下载替换（已由 CI 自动化）；已备份 .env/uploads |
| **pm2 命令找不到** | `Command 'pm2' not found` | npm 全局 bin 不在 PATH | `export PATH="$PATH:$(npm prefix -g)/bin"` |
| **头像 404** | 换头像显示不出来 | 后端写 `process.cwd()/uploads/avatars`，nginx alias 写错目录 | nginx alias 对齐 `/opt/kb/ai-knowledge-base/uploads/avatars/` |
| **头像缓存不刷新** | 换了头像还是旧的 | 头像 URL 固定 + nginx `expires 7d` | 前端 URL 带版本号 `?v=n` + nginx no-store |
| **历史图片叠满屏** | 带图消息重进会话后满屏"图片"+卡死 | 后端把 JSON 字符串直接返回，前端 `v-for` 字符串按字符遍历 | 后端 JSON.parse 成数组 + 前端防御（见 docs 记录） |
| **切页卡顿** | 进出对话页卡 | Transition out-in 串行处理大组件树 + Canvas 每次重建 5000 粒子 | 去掉串行过渡、首页 KeepAlive 暂停/恢复、流式 rAF 节流、渲染缓存 |

## 五、CI 自动部署（push 即上线）

**原理**：本地 `git push` → GitHub Actions：
1. **check job**：类型检查 + 37 个单测 + 前端/后端构建（每次 push 都跑，防坏代码上线）；
2. **deploy job**（仅 main 分支）：SSH 登录服务器 → ghfast.top 下载新代码 → 备份 .env/uploads → 替换 → install → 迁移 → 构建 → `pm2 restart kb-server`。

**配置过的三样东西**：
| 配置 | 在哪 | 值 |
|---|---|---|
| Secret `SERVER_HOST` | GitHub → Settings → Secrets → Actions | `159.75.52.172` |
| Secret `SSH_PRIVATE_KEY` | 同上 | `~/.ssh/kb_ci` 私钥全文 |
| 公钥授权 | 服务器 `~/.ssh/authorized_keys` | `kb_ci.pub` 内容 |

> 没配 Secrets 时 deploy job 自动跳过（`Check deploy config` 步骤），CI 仍绿——安全兜底。

## 六、日常运维速查（贴到服务器直接跑）

```bash
# 看后端日志（报错排查首选）
pm2 logs kb-server --lines 50
# 重启后端
pm2 restart kb-server
# 看容器状态
docker ps
# 看 PostgreSQL 数据
docker exec kb-postgres psql -U kb -d kb -c "SELECT count(*) FROM documents;"
# nginx 配置检查/重载
nginx -t && systemctl reload nginx
# 磁盘/内存
free -h; df -h /
# 手动触发一次部署 = push 一次代码（或等下一次 push）
```

**日常更新 = 不用碰服务器**：本地改代码 → `git push` → 等 GitHub Actions 绿 → 刷新网站即可。
