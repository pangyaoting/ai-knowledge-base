# 阶段 4+：增量向量化（内容哈希去重）

> 一句话：上传时给文件算 SHA-256 指纹，**同名 + 同内容的文档直接跳过**——
> 重传没变的目录/文件几乎零成本（不存盘、不解析、不重复嵌入），改动过的才重新向量化。

## 一、背景

原逻辑：上传/替换文档一律重新解析 + 全部重新嵌入（按 token 计费、慢）。
上传项目目录（几千文件）时，即使只改了几个文件，也要全量重嵌入一遍。

## 二、实现

- `documents` 表新增 `content_hash`（文件原始字节的 SHA-256，与文件名无关）；
- 上传时先算哈希，查同知识库内「同名 + 同哈希」的文档：
  - **命中 → 跳过**：不存盘、不建记录、不入队，返回 `{ skipped: true, filename }`；
  - **同名不同哈希 → 正常替换**（沿用 replacing 机制）；
  - **新文件 → 正常处理**；
- 附件（图片/二进制）同样去重（省磁盘）；
- 前端批量上传统计跳过数：toast 提示「N 个内容未变化已跳过」，解析环形进度不计入跳过文件；
  替换文档时若内容没变也提示「无需重新向量化」；
- 编辑内容（updateContent）不改哈希——因为比较的是**磁盘原文件内容**，编辑后的知识库内容与重传判定无关。

## 三、自测记录

| 场景 | 结果 |
|---|---|
| 首次上传 a.txt | ✅ 正常创建（status pending → 后台处理） |
| 重复上传同名同内容 | ✅ `skipped: true`（不重复解析/嵌入） |
| 同名改内容再传 | ✅ 正常替换（旧文档 replacing，新文档处理） |
| 改名同内容（b.txt） | ✅ 正常创建（文件名不同不跳过） |
| content_hash 落库 | ✅ a v1 与 b.txt 同哈希、改版后哈希不同 |
