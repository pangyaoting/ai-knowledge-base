# 阶段 4+：研究报告（一键产出成品报告）

> 一句话：丢一个主题，系统自动拆子问题、查资料、分节撰写、汇总成完整报告，每段带引用可溯源。
> 从"答一句"变成"产出一份成品"——产品形态从"对话工具"升级为"研究工作台"。

---

## 一、大白话：和聊天有什么不同

| | 对话（Chat） | 研究报告（Research） |
|---|---|---|
| 形态 | 一问一答 | 一份结构化成品（引言/正文/结论） |
| 范围 | 一次只回答一个问题 | 主题自动拆成 3~5 个子问题，全覆盖 |
| 产出 | 聊天记录 | Markdown 报告，可导出、可引用溯源 |
| 时长 | 秒级流式 | 1~2 分钟异步任务（值得等，因为是成品） |

## 二、实现拆解

### 1. 生成管线（ReportProcessor，BullMQ worker 后台跑）

```
主题 → ① LLM 拆解 3~5 个子问题
     → ② 每个子问题：复用 RagService 混合检索 + LLM 撰写小节（并行，来源编号全局统一）
     → ③ LLM 汇总：标题 + 引言 + 正文（保留 [来源N]）+ 结论
     → 落库 content/sections/sources，status=done
```

- **异步**：1~2 分钟不能阻塞 HTTP 请求，复用 BullMQ（新队列 `report-generate`，单并发，失败重试一次）；
- **进度**：`status` + `step`（1=拆解 2=撰写 3=汇总），前端 1.5s 轮询显示"正在拆解研究问题…"；
- **复用**：检索直接调用 ChatModule 导出的 `RagService.retrieve`（相关性门控、归属隔离全继承）；
- **来源编号全局统一**：多个小节可能引用同一段，`Map<chunkId, number>` 去重编号。

### 2. 数据模型

```prisma
model Report {
  topic    String   // 研究主题
  status   String   // pending / processing / done / failed
  step     Int      // 1=拆解 2=撰写 3=汇总 4=完成
  content  String?  // 最终 Markdown
  sections Json?    // [{ index, question, content }]
  sources  Json?    // [{ number, documentId, chunkIndex, filename, similarity }]
  error    String?
}
```

### 3. 前端（/research）

- 左列表（状态徽章）+ 右主区；新建表单（主题 + 检索范围：全部/指定）；
- 生成中进度文案；完成后 Markdown 渲染（复用对话的渲染与代码复制）+ **引用来源可点击 → DocPreviewDrawer 定位原文**（组件复用）；
- 导出 Markdown 纯前端 Blob 下载（内容已是 Markdown，无需后端）。

## 三、面试话术

- "研究报告是**多步研究管线**不是一次生成：拆解→并行检索→分节撰写→汇总，每一步可追溯；因为耗时，走独立的 BullMQ 队列 + 状态机（pending/processing/step/done/failed）。"
- "复用点：检索直接调聊天模块导出的 RagService，相关性门控和数据隔离白拿；引用定位直接复用预览抽屉组件。"
- "产品叙事：同样花用户的 token，对话只能答一句，研究报告产出一份带证据链的成品——这是'工具'和'工作台'的区别。"
