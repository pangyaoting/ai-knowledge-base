## 第一部分：项目科普 —— RAG 到底是什么

### 1.1 一句话解释

RAG（Retrieval-Augmented Generation，检索增强生成）= **先查资料，再回答问题**。

就像开卷考试：大模型（LLM）本身是个"闭卷考生"，它只记得训练时学过的知识，会胡说八道（幻觉）。RAG 就是在它回答前，先从你的知识库里检索出相关资料，塞进提示词里，让它"看着资料回答"，准确率大幅提升。

### 1.2 完整工作流程（两个阶段）

```
【阶段一：入库（Indexing）—— 文档上传时做】

用户上传 PDF/Word/Markdown
        ↓
  ① 文档解析（提取纯文本）
        ↓
  ② 文本分块（切成一段段 chunk）
        ↓
  ③ 向量化（每个 chunk 调 Embedding 模型，变成一串数字=向量）
        ↓
  ④ 存入向量数据库（chunk 原文 + 向量 + 元数据）

【阶段二：查询（Retrieval & Generation）—— 每次提问时做】

用户提问
   ↓
  ⑤ 问题向量化（同一个 Embedding 模型把问题变成向量）
        ↓
  ⑥ 向量检索（在向量库里找语义最相似的 Top-K 个 chunk）
        ↓
  ⑦ 组装 Prompt（系统提示词 + 检索到的资料 + 用户问题 + 历史对话）
        ↓
  ⑧ 调 LLM（DeepSeek），SSE 流式返回答案
        ↓
  ⑨ 前端逐字渲染 + 显示引用来源
```

| 维度 | 普通后台管理系统 | AI 知识库（RAG） |
|------|----------------|-----------------|

### 1.4 核心概念（面试必问）

- **Embedding（嵌入/向量化）**：把一段文字变成一串数字（如 1024 维向量），语义相近的文字，向量距离就近。这是"语义检索"的基础。
- **Chunk（分块）**：文档不能整篇丢给模型（太长、太贵、检索不精准），要切成小块。块太大→检索不精准；块太小→丢失上下文。
- **Top-K 检索**：每次提问，从向量库取回最相似的 K 个片段（通常 K=3~5）。
- **SSE（Server-Sent Events）**：服务器单向推送流，基于 HTTP，比 WebSocket 轻量，专门适合"服务器持续吐数据、客户端只接收"的 AI 流式输出场景。
- **Token**：LLM 处理文本的最小单位，约 1 个汉字 ≈ 1.5~2 token。API 按 token 计费。
- **混合检索**：向量检索（语义匹配）+ 关键词检索（BM25，精确匹配术语/编号）结合，召回率更高。
- **幻觉（Hallucination）**：模型编造不存在的事实。RAG 是缓解幻觉的主流方案。

## 第五部分：面试亮点预埋清单

1. **工程化**：pnpm monorepo + 前后端类型共享 + CI/CD + Docker
2. **SSE 流式**：为什么选 SSE 不选 WebSocket；首字延迟 < 500ms
3. **分块策略**：固定/递归/语义三种对比，chunk size 和 overlap 怎么调
4. **Embedding 选型**：bge-m3 vs OpenAI vs 智谱，中文效果、维度、成本
5. **pgvector**：一个库存业务+向量；cosine 距离；hnsw 索引
6. **混合检索**：向量（语义）+ BM25（关键词），解决术语精确匹配
7. **上下文管理**：滑动窗口控制 token
8. **安全**：bcrypt + JWT 双 Token + Redis 限流 + 2FA
9. **性能优化**：Nginx Gzip、缓存、Embedding 批量请求、数据库索引
10. **AI 协作**：用 AI 辅助开发，如何 review AI 代码、设计 prompt 提效
