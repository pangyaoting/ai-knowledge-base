## 1. 环境准备

### 1.1 检查已安装的工具

打开 PowerShell，依次执行：

```powershell
node -v        # 检查 Node.js 版本，需要 >= 20
npm -v         # 检查 npm
pnpm -v        # 检查 pnpm
git --version  # 检查 Git
docker -v      # 检查 Docker（阶段0末尾才需要）
```

**知识点：**
- NestJS 10 和 Vite 5 都要求 Node.js >= 18，推荐 20 LTS
- 如果你的 Node 版本低于 20，必须先升级

### 1.2 升级 Node.js（以 v16 为例）

**方式一：用 winget 升级（推荐，Windows 自带）**

```powershell
winget install OpenJS.NodeJS.LTS --accept-package-agreements --accept-source-agreements
```

**方式二：手动下载**

去 https://nodejs.org 下载 LTS 版本，双击安装覆盖旧版本。

**升级后必须新开一个终端窗口**，旧终端的环境变量还是旧的。验证：

```powershell
node -v   # 应显示 v20.x 或更高
```

### 1.3 安装 pnpm

```powershell
npm install -g pnpm
```

**为什么用 pnpm 而不是 npm？**
- 快 2-3 倍（硬链接 + 内容寻址存储）
- 节省磁盘空间（同一个包只存一份）
- 原生支持 monorepo（workspace）
- 命令几乎和 npm 一样：`npm install` → `pnpm install`

### 1.4 安装 Docker Desktop

去 https://www.docker.com/products/docker-desktop/ 下载安装，启动后等鲸鱼图标变绿。

Docker 用来一键启动 PostgreSQL 和 Redis，不用手动在 Windows 上装数据库。

## 2. 创建 monorepo 目录结构

### 2.1 什么是 monorepo？

monorepo 就是把前端、后端、共享代码放在**同一个 Git 仓库**里管理。

```
monorepo（一个仓库）
├── apps/server   # 后端
├── apps/web      # 前端
└── packages/shared  # 前后端共享的 TypeScript 类型
```

**好处：**
- 前后端共享类型定义（后端定义的 User 类型，前端直接 import）
- 一个命令同时启动前后端
- 统一的代码规范和依赖管理

### 2.2 创建目录

```powershell
# 创建项目根目录
mkdir D:\项目\主项目
cd D:\项目\主项目

# 创建所有子目录（PowerShell 一键创建）

  "apps\server\src\common\interceptors",
  "apps\server\src\modules\health",

$dirs | ForEach-Object { New-Item -ItemType Directory -Force -Path $_ | Out-Null }
```

## 3. 根配置文件

### 3.1 `pnpm-workspace.yaml` — 声明 monorepo 工作区

```yaml
packages:
  - 'apps/*'      # apps 下的所有目录都是独立的包
  - 'packages/*'  # packages 下的也是
```

**作用：** 告诉 pnpm 这个仓库里有哪些子项目，执行 `pnpm install` 时会自动安装所有子项目的依赖，并把它们互相链接起来。

### 3.2 `package.json` — 根项目配置

```json
{
  "name": "ai-knowledge-base",
  "version": "1.0.0",
  "private": true,
  "scripts": {
    "dev:web": "pnpm --filter @app/web dev",
    "dev:server": "pnpm --filter @app/server start:dev",
    "build": "pnpm -r build",
    "lint": "pnpm -r lint",
    "format": "prettier --write \"**/*.{ts,vue,js,json,md}\"",
    "prepare": "husky install"
  },
  "devDependencies": {
    "@commitlint/cli": "^19.5.0",
    "@commitlint/config-conventional": "^19.5.0",
    "husky": "^9.1.6",
    "lint-staged": "^15.2.10",
    "prettier": "^3.3.3"
  },
  "engines": {
    "node": ">=20.0.0",
    "pnpm": ">=8.0.0"
  }
}
```

**知识点：**
- `"private": true` — 根项目不会被发布到 npm
- `pnpm --filter @app/web dev` — 只在名为 `@app/web` 的子项目里执行 `dev` 脚本
- `pnpm -r build` — 在所有子项目里递归执行 `build`
- `"prepare": "husky install"` — `pnpm install` 后自动执行，初始化 husky 钩子
- 根目录只放**所有子项目共用的**开发工具（prettier、husky、commitlint）

### 3.3 `.npmrc` — pnpm 配置

```ini
shamefully-hoist=true
strict-peer-dependencies=false
auto-install-peers=true
registry=https://registry.npmmirror.com
verify-deps-before-run=false
```

**逐行解释：**
- `shamefully-hoist=true` — 把依赖提升到根 node_modules（某些包找不到依赖时需要）
- `strict-peer-dependencies=false` — 不严格检查 peerDependencies，避免安装报错
- `auto-install-peers=true` — 自动安装 peer dependencies
- `registry=https://registry.npmmirror.com` — 使用淘宝镜像（国内下载快）
- `verify-deps-before-run=false` — 跳过 pnpm 11 的运行前依赖检查（避免构建脚本批准问题）

### 3.4 `.gitignore` — Git 忽略规则

```gitignore
node_modules/
dist/
build/
*.tsbuildinfo
.env
.env.local
.vscode/*
!.vscode/settings.json
!.vscode/extensions.json
.idea/
.DS_Store

*.log

```

**重点：**
- `.env` 必须忽略（里面有 API Key、密码等敏感信息）
- `node_modules/`、`dist/` 是生成的，不提交
- `uploads/*` 忽略但保留 `.gitkeep`（保持空目录结构）

### 3.5 `.prettierrc` — 代码格式化规则

```json
{
  "semi": true,
  "singleQuote": true,
  "trailingComma": "all",
  "printWidth": 100,
  "tabWidth": 2,
  "endOfLine": "auto",

```

### 3.6 `commitlint.config.cjs` — Git 提交信息规范

```js
module.exports = {
  extends: ['@commitlint/config-conventional'],
  rules: {
    'type-enum': [
      2,
      'always',
      ['feat', 'fix', 'docs', 'style', 'refactor', 'perf', 'test', 'chore', 'ci', 'revert'],
    ],
  },
};
```

**作用：** 强制提交信息格式为 `type: 描述`，例如：
- `feat: 添加用户登录功能`
- `fix: 修复token刷新bug`
- `chore: 初始化项目骨架`

### 3.7 `.lintstagedrc.cjs` — 暂存区检查

```js
module.exports = {
  '*.{ts,vue,js}': ['eslint --fix', 'prettier --write'],
  '*.{json,md}': ['prettier --write'],
};
```

**作用：** `git commit` 时只检查**本次提交的文件**（不是全项目），自动修复和格式化。

## 4. Docker 数据库配置

### 4.1 `docker-compose.yml`

```yaml
services:
  postgres:
    image: pgvector/pgvector:pg16        # PostgreSQL 16 + pgvector 向量扩展
    container_name: kb-postgres
    restart: unless-stopped
    ports:
      - '5432:5432'
    environment:
      POSTGRES_USER: ${DB_USER:-kbuser}
      POSTGRES_PASSWORD: ${DB_PASSWORD:-kbpassword}
      POSTGRES_DB: ${DB_NAME:-knowledge_base}
    volumes:
      - postgres-data:/var/lib/postgresql/data
    healthcheck:
      test: ['CMD-SHELL', 'pg_isready -U kbuser -d knowledge_base']
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    container_name: kb-redis
    restart: unless-stopped
    ports:
      - '6379:6379'
    command: redis-server --appendonly yes
    volumes:
      - redis-data:/data
    healthcheck:
      test: ['CMD', 'redis-cli', 'ping']
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  postgres-data:
  redis-data:
```

**知识点：**
- `pgvector/pgvector:pg16` — 这个镜像已经预装了 pgvector 扩展，不用手动安装
- `volumes` — 数据持久化，容器删了数据还在
- `healthcheck` — 健康检查，确认数据库真正启动好了
- `${DB_USER:-kbuser}` — 读环境变量，没有就用默认值 kbuser

### 4.2 `.env` 和 `.env.example`

`.env` 是真实的环境变量（不提交 Git），`.env.example` 是模板（提交 Git）。


- Prisma、NestJS 都能直接读取

### 5.4 `apps/server/src/main.ts` — 后端入口

```typescript
import { NestFactory } from '@nestjs/core';
import { ValidationPipe, Logger } from '@nestjs/common';
import { DocumentBuilder, SwaggerModule } from '@nestjs/swagger';
import { ConfigService } from '@nestjs/config';
import { AppModule } from './app.module';
import { HttpExceptionFilter } from './common/filters/http-exception.filter';
import { TransformInterceptor } from './common/interceptors/transform.interceptor';

async function bootstrap() {
  const logger = new Logger('Bootstrap');
  const app = await NestFactory.create(AppModule);

  const configService = app.get(ConfigService);
  const port = configService.get<number>('SERVER_PORT', 3000);

  // 所有接口加 /api 前缀
  app.setGlobalPrefix('api');

  // 允许前端开发服务器跨域
  app.enableCors({
    origin: ['http://localhost:5173', 'http://localhost:4173'],
    credentials: true,
  });

  // 全局参数校验：自动校验 DTO、剥离未定义字段、类型转换
  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,
      transform: true,
      forbidNonWhitelisted: true,
    }),
  );

  // 全局异常过滤器 + 统一响应格式
  app.useGlobalFilters(new HttpExceptionFilter());
  app.useGlobalInterceptors(new TransformInterceptor());

  // Swagger 接口文档：访问 http://localhost:3000/api/docs
  const swaggerConfig = new DocumentBuilder()
    .setTitle('AI 知识库 API')
    .setDescription('AI 知识库问答平台接口文档')
    .setVersion('1.0')
    .addBearerAuth()
    .build();
  const document = SwaggerModule.createDocument(app, swaggerConfig);
  SwaggerModule.setup('api/docs', app, document);

  await app.listen(port);
  logger.log(`后端服务已启动: http://localhost:${port}`);
  logger.log(`Swagger 文档: http://localhost:${port}/api/docs`);
}

bootstrap();
```

**这里做了 5 件事：**
1. 全局路由前缀 `/api`
2. CORS 跨域配置
3. 全局参数校验管道（class-validator 自动校验请求参数）
4. 全局异常过滤器 + 统一响应拦截器
5. Swagger 自动生成接口文档

### 5.6 Prisma 服务

`src/common/prisma/prisma.service.ts`：

```typescript
import { Injectable, OnModuleInit, OnModuleDestroy } from '@nestjs/common';
import { PrismaClient } from '@prisma/client';

@Injectable()
export class PrismaService extends PrismaClient implements OnModuleInit, OnModuleDestroy {
  async onModuleInit() {
    await this.$connect();
  }
  async onModuleDestroy() {
    await this.$disconnect();
  }
}
```

`src/common/prisma/prisma.module.ts`：

```typescript
import { Global, Module } from '@nestjs/common';
import { PrismaService } from './prisma.service';

@Global()
@Module({
  providers: [PrismaService],
  exports: [PrismaService],
})
export class PrismaModule {}
```

**知识点：**
- `PrismaService` 继承 `PrismaClient`，在模块启动时自动连接数据库
- `@Global()` 标记为全局模块，其他模块不用 import 就能直接注入 `PrismaService`
- 以后任何 Service 里写 `constructor(private prisma: PrismaService) {}` 就能操作数据库

```typescript
export class RedisService extends Redis implements OnModuleDestroy {
  private readonly logger = new Logger(RedisService.name);

  constructor(private configService: ConfigService) {
```

### 5.8 全局异常过滤器

`src/common/filters/http-exception.filter.ts`：

```typescript
import { ExceptionFilter, Catch, ArgumentsHost, HttpException, HttpStatus, Logger } from '@nestjs/common';
import { Request, Response } from 'express';

@Catch()
export class HttpExceptionFilter implements ExceptionFilter {
  private readonly logger = new Logger(HttpExceptionFilter.name);

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    let status = HttpStatus.INTERNAL_SERVER_ERROR;
    let message = '服务器内部错误';

    if (exception instanceof HttpException) {
      status = exception.getStatus();
      const res = exception.getResponse();
      message =
        typeof res === 'string'
          ? res
          : (res as Record<string, unknown>).message instanceof Array
            ? ((res as Record<string, unknown>).message as string[]).join('; ')
            : ((res as Record<string, unknown>).message as string) || exception.message;
    } else if (exception instanceof Error) {
      message = exception.message;
      this.logger.error(`未处理的异常: ${exception.stack}`);
    }

    response.status(status).json({
      code: status,
      message,
      data: null,
      path: request.url,
      timestamp: new Date().toISOString(),
    });
  }
}
```

**作用：** 后端抛出的任何异常都会被这里捕获，返回统一格式的 JSON，不会把堆栈信息直接暴露给前端。

### 5.9 统一响应拦截器

`src/common/interceptors/transform.interceptor.ts`：

```typescript
import { Injectable, NestInterceptor, ExecutionContext, CallHandler } from '@nestjs/common';
import { Observable } from 'rxjs';
import { map } from 'rxjs/operators';

@Injectable()
export class TransformInterceptor<T> implements NestInterceptor<T, { code: number; message: string; data: T }> {
  intercept(_context: ExecutionContext, next: CallHandler): Observable<{ code: number; message: string; data: T }> {
    return next.handle().pipe(
      map((data) => ({
        code: 0,
        message: 'success',
        data,
      })),
    );
  }
}
```

**效果：** Controller 里 `return { name: '张三' }`，前端收到的是：

```json
{ "code": 0, "message": "success", "data": { "name": "张三" } }
```

所有接口格式统一，前端处理起来更方便。

### 8.2 可能遇到的问题

**问题 1：下载慢/超时**

在 `.npmrc` 里加淘宝镜像：
```ini
registry=https://registry.npmmirror.com
```

**问题 2：pnpm 11 提示 `Ignored build scripts`（ERR_PNPM_IGNORED_BUILDS）**

pnpm 10+ 的安全机制：默认拦截所有依赖包的 postinstall 构建脚本（防止供应链攻击），必须显式白名单放行，否则 `pnpm install` 直接失败退出。

**坑：pnpm 11 把配置键从 `onlyBuiltDependencies` 改名成了 `allowBuilds`**，旧键会被静默忽略（不会报"键不存在"，而是直接把包列为 ignored → 装依赖失败）。本地不报错是因为 node_modules 已装好、install 显示 "Already up to date" 不会重跑构建脚本；CI 全新安装必踩。正确写法：

```yaml
allowBuilds:
  '@nestjs/core': true    # NestJS 赞助提示脚本
  '@prisma/client': true  # 安装时自动生成 Prisma Client
  '@prisma/engines': true # 下载查询引擎二进制
  esbuild: true           # Vite 打包依赖的 esbuild 二进制
  prisma: true            # Prisma CLI 预安装脚本
  vue-demi: true          # @vueuse 依赖的 Vue 2/3 版本切换
```

改完重新 `pnpm install` 即可（`--frozen-lockfile` 同样生效，锁文件无需改动）。

**问题 3：Prisma Client 没生成**

```powershell
cd apps/server
npx prisma generate
```

如果下载引擎慢，设置国内镜像：
```powershell
$env:PRISMA_ENGINES_MIRROR = "https://registry.npmmirror.com/-/binary/prisma"
npx prisma generate
```

**问题 4：页面行为是"旧代码"（Vite 内存模块缓存过期）**

**现象**：改了代码但页面表现还是旧的——比如"知识库创建后要手动刷新才显示""点按钮没反应"，连 Ctrl+Shift+R 都无效。

**根因**：Vite dev 服务器把转换后的模块缓存在**自己的内存**里；Windows 上文件监听（chokidar）偶尔漏掉个别文件的变更事件，Vite 就一直提供该文件的**旧版本**。浏览器（哪怕是全新浏览器）从 Vite 拿到的就是这个旧模块 → 报 `does not provide an export named 'xxx'` 之类的运行时错误，页面白屏/行为异常。

**排查技巧（面试可讲）**：我用无头 Chrome（DevTools 协议，纯 Node 实现，无需装 Puppeteer）自动化复现了用户操作，抓到控制台里的 `SyntaxError: ... does not provide an export named 'downloadDocumentFile'`，再用全新无痕浏览器二次确认是**服务端**在吐旧模块，而不是用户浏览器缓存。

**修复**：重启 Vite 即可（内存缓存清空，重新从磁盘转换）：

```powershell
# 停掉 vite dev 进程，重新 pnpm dev:web
```

之后浏览器强制刷新一次（Ctrl+Shift+R），让浏览器也丢掉自己缓存过的模块。

## 11. 关键概念总结

| 概念 | 一句话理解 |
|------|-----------|
| monorepo | 前后端放一个仓库，pnpm workspace 管理 |
| NestJS Module | 每个功能一个模块，包含 Controller（路由）+ Service（逻辑） |
| 依赖注入 | `@Injectable()` 标记的服务，NestJS 自动创建和传递实例 |
| Prisma | 类型安全的 ORM，写 TS 就能操作数据库，不用写 SQL |
| pgvector | PostgreSQL 的向量扩展，一个库同时存业务数据和向量 |
| SSE | 服务器单向推送，适合 AI 流式输出 |
| DTO | Data Transfer Object，定义接口参数格式，配合 class-validator 自动校验 |
| 拦截器/过滤器 | NestJS 的 AOP 机制，统一处理响应格式和异常 |
| Tailwind CSS 变量主题 | 颜色用 CSS 变量定义，切换类名就能切换主题 |
| pnpm filter | `pnpm --filter @app/web dev` 只在指定子项目执行命令 |
