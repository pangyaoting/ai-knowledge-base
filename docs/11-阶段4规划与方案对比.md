## 2. 混合检索（向量 + BM25）

### 问题

纯向量检索有两个短板：
1. **精确术语**：搜"Vue3"这种专有名词，语义检索可能召回"前端框架"的段落，但漏掉字面包含"Vue3"的段落
2. **数字/编号**："第 2 章""RFC 8259"这类，语义向量区分度差

### 方案对比

| 方案 | 做法 | 优点 | 缺点 | 复杂度 |
|------|------|------|------|--------|
| A. 纯向量（现状） | 只用余弦距离 | 已实现 | 术语召回差 | - |
| **B. 向量 + BM25 混合（推荐）** | 两个检索器各取 Top-K，**RRF 加权融合** | 语义 + 关键词互补，召回率明显提升 | 要装 `pg_bigm`/`zhparser` 或写内存 BM25 | 中 |
| C. 只加关键词过滤 | 先用 SQL `LIKE`/全文索引过滤再向量排序 | 简单 | 召回逻辑粗糙 | 低 |

**推荐 B 的轻量实现**（不用装 Postgres 插件）：内存里对全部候选 chunk 算 BM25 分数（chunk 量级几千条，够快），与向量分数 RRF 融合，取 Top-5。

**RRF（Reciprocal Rank Fusion）**：`score = 1/(k + rank1) + 1/(k + rank2)`，两个检索结果按名次融合——不依赖分数可比性，是业界标准做法（面试点）。

**预期效果（可量化）**：对包含专有名词的问题，Top-5 召回相关性提升（实测后写数字）。

## 3. 数据看板（ECharts）

### 要展示什么

| 图表 | 数据来源 |
|------|----------|
| 对话次数折线图（近 7 天） | chat_messages 按天聚合 |
| Token 消耗（近 7 天） | 新增 usage 记录（每次问答后落库 token 数） |
| 热门问题 TOP10 | 按用户消息内容分组计数 |
| 知识库概览 | 各知识库文档数/chunk 数 |

### 关键决策：Token 统计怎么来

DeepSeek 流式响应的 `chat.completions.create` 完成时返回 `usage` 字段（prompt/completion tokens），但**流式模式默认不返回 usage**——需要开启 `stream_options: { include_usage: true }`，且 usage 会作为最后一个 chunk 出现。这是实现的坑，实现时处理。

### 方案对比

| 方案 | 做法 | 优劣 |
|------|------|------|
| A. 存数据库（推荐） | 每次问答后把 usage 写入新表 `chat_usage` | 数据可回溯、可聚合、面试好讲"埋点统计" |
| B. 只统计前端 | 前端拿 delta 长度估算 | 不准，且刷新丢失 |
| C. 实时推送 | WebSocket/SSE 推最新数据 | 炫但复杂，阶段 4 不需要 |

**推荐 A**：`chat_usage` 表 + 统计接口聚合 + 前端 ECharts。

## 4. 2FA 双因素认证（TOTP）

### 原理（面试必讲）

TOTP（Time-based One-Time Password）：**密钥（secret）+ 当前时间** → HMAC-SHA1 → 截断成 6 位数字，**每 30 秒变化一次**。Google Authenticator 等 App 本地计算，服务器用同一算法验证——**两边都离线可算，不用发短信**。

### 流程

```
设置页 → 后端生成 secret → 返回二维码（otpauth:// 协议）
       → 用户扫码（Authenticator App）
       → 输入 App 上的 6 位码 → 后端验证 → 开启 2FA
登录时 → 密码 + 6 位码 → 都通过才发 token
```

### 方案对比

| 库 | 说明 | 选择 |
|----|------|------|
| `otplib`（推荐） | 正宗 TOTP 实现，纯 JS，API 简单 | ✅ 用它 |
| `speakeasy` | 老牌，功能全但更重 | 备选 |
| 手写 TOTP | 就几十行，但容易出边界 bug | 不推荐（有轮子别造） |
| 二维码 | `qrcode` 库生成 base64 图片 | ✅ 前端展示 |

### 需要做的

1. 用户表加 `twoFactorSecret`、`twoFactorEnabled` 字段
2. 设置页：生成 secret + 二维码 + 验证绑定
3. 登录流程：开启 2FA 的用户，密码验证后还要验 6 位码
4. **恢复码**（可选增强）：绑定成功生成 8 个一次性恢复码，防丢手机
