# 阶段 4+：体验打磨（Toast/骨架屏）、文件夹上传、一键启动根治

> 一句话：给全站加了统一的 Toast 反馈与列表骨架屏；文件夹上传保持"文件夹形态"（目录树展示、不支持文件点名过滤）；
> 顺带根治了"开机一键启动误报 Database not ready"与"WSL 重启后文档队列卡死"两个环境顽疾。

---

## 一、一键启动"Database not ready"根治（重点）

### 问题现象

开机后跑 `一键启动.bat`，窗口里长时间卡住并报错，类似：

```
Test-NetConnection - ::1:5432
Attempting TCP connect
Waiting for response
[ERROR] Database not ready in 90s.
```

### 根因（两层）

1. **慢探测拖垮等待预算**：脚本用 `Test-NetConnection localhost -Port 5432` 探测数据库端口。
   端口还没通时，每次调用要干等 10~20 秒（上面的英文就是它在干等 TCP 超时），
   90 秒预算被几次慢探测耗光 → 误报超时，即使数据库其实马上就好。
2. **启动时序靠猜**：原来 docker 就绪脚本在独立最小化窗口"后台跑 + 脚本自己等"，bat 只靠探端口，
   二者没有真正的先后关系，端口开了 ≠ postgres 真的能连（容器启动中）。

### 修复（治本）

- **`keep-docker-running.sh` 重写为"前台就绪脚本"**：彻底清理残留（dockerd + containerd + shim +
  pid/socket，残留 containerd 会占 socket 导致新 dockerd 起不来）→ 等 dockerd 可连（60s）→
  compose 拉起 → 等**容器 HEALTHCHECK 通过** → 等端口绑定 → 全部就绪才 `exit 0`；
- **`keepalive.sh`**：独立保活（`tail -f`），防止 WSL2 VM 空闲 60s 被系统回收（回收会断掉所有容器端口）；
- **`一键启动.bat`**：docker 步骤改为**前台同步执行**（窗口直接显示就绪进度，失败看得到原因）；
  端口探测换成自写的 **`check-port.bat`**（TcpClient + 500ms 超时，实测开端口 306ms / 关端口 804ms），
  彻底告别 Test-NetConnection 的 10~20 秒卡顿；
- 冷启动实测：`wsl --shutdown`（等价重启）→ 跑新脚本 → **16.3 秒全就绪，exit 0**；
  幂等场景（已健康）0.7 秒返回。

### 第二坑：wslpath 中文路径乱码（GBK 管道）

一键启动里用 `wsl -d alpine -- wslpath "%ROOTN%"` 把 Windows 路径转成 WSL 路径，
结果变成 `/mnt/d/椤圭洰/涓婚」鐩?`——**wslpath 的 UTF-8 输出经过 cmd 的 `for /f` 管道时被按 GBK
解码，中文目录名必然乱码**。修复：不再做任何"输出回传"，在 bat 里直接用字符串拼接构造
`/mnt/<盘符小写>/<目录>`（盘符小写支持 C~H 盘），中文路径作为参数直接传给 `wsl.exe`——
这个方向（Windows Unicode → wsl 转 UTF-8）是可靠的。

### 第三坑：keep-docker-running.sh 硬编码路径

脚本里 `cd /mnt/d/项目/主项目` 写死，**项目移动/复制到别处就失效**。
改为 `SCRIPT_DIR=$(cd "$(dirname "$0")" && pwd)` 用脚本自身位置推导，任意路径都能跑。

### 可移植性验证（已实测）

把启动相关文件整体复制到全新的中文路径 `D:\测试移动\` 再跑一键启动：
路径自动适配、无乱码、keeper 从新位置幂等拉起容器、全链路就绪退出 0。
**结论：整个项目目录移动/复制到其他盘或目录（含中文名）都可以直接跑**，
前提是整目录一起搬（含 `.env`、`docker-compose.yml`、脚本），且盘符在 C~H 范围内；
`.env` 含密钥，注意不要提交到公开仓库。

## 二、BullMQ worker 断线不恢复（顺带根治）

排查文件夹上传时发现：`wsl --shutdown` 后主 Redis 连接自动重连成功，但**文档/报告两个队列 worker
不消费任务**（文档一直 pending）。原因：BullMQ 连接没配显式 `retryStrategy`，Redis 重启后 worker
的重连不可靠（已知坑）。修复：两个队列服务的 `connection` 都加上
`retryStrategy: (times) => Math.min(times * 500, 5000)`，Redis 重启后 worker 能恢复消费。

## 三、文件夹上传：保持"文件夹形态"

### 需求

- 选目录上传后，文档列表**按目录树展示**（📁 文件夹可展开/折叠、文件按层级缩进），而不是把所有
  文件平铺成 `docs/子目录/a.md` 一条条；
- 目录里有不支持的文件 → **过滤掉并逐个点名提示**（"以下 2 个文件不支持，未上传：xx.exe、yy.png"）。

### 实现

- 后端零改动：目录上传本来就把 `webkitRelativePath`（如 `docs/子目录/a.md`）存进 `filename`，
  前端从文件名解析出目录结构即可；
- **目录树**：`buildDocTree()` 按 `/` 拆路径建树（文件夹在前、文件在后，各按名称排序），
  表格渲染可展开/折叠的文件夹行 + 按层级缩进的文件行，工具条提供"全部展开/全部折叠"；
  搜索时自动切回扁平列表（显示完整相对路径，方便定位）；
- **展开状态用 `reactive(Set)` 按路径记录**——踩坑：树由 computed 每次重建（全新对象），
  若把 `expanded` 挂在节点对象上，修改普通对象**不触发响应式更新**，展开/折叠会失灵；
  放 Set 里，模板读 `expandedPaths.has(path)` 才响应（自测抓到的真实 bug）；
- **待上传列表**同样按目录分组展示（📁 文件夹头 + 组内文件显示纯文件名）；
- **点名过滤**：`addPendingFiles` 收集不支持的完整文件名列表，Toast 逐个列出（最多 6 个 + 总数）。

## 四、全站 Toast 与骨架屏

- **Toast**：`src/composables/useToast.ts`（模块级响应式状态，任何组件可用）+ `ToastContainer.vue`
  （右上角堆叠、自动消失、可手动关闭，成功/错误/提示三态）。替换了知识库/文档/对话/报告/设置/
  模型配置等页面的零散内联提示；
- **骨架屏**：`Skeleton.vue`（灰色占位块 + animate-pulse）+ `ListSkeleton` / `DashboardSkeleton`，
  替换知识库/文档/会话/报告/模型配置列表与看板的转圈加载。
