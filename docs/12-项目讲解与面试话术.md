# 项目讲解与面试话术（定稿用）

> 面试原则（2026-2027 市场）：**不问"你做了什么"，问"你怎么做决定的"**。
> 每个模块按"背景→问题→约束→方案对比→最终选择→结果→复盘"讲，必须带量化数字。
> 使用方法：先背"简历描述"，再逐模块练习"讲解脚本"，最后过一遍"高频问题"。

## 1. 简历项目描述（直接可用）

### AI 知识库问答平台 | 全栈个人项目 | 2026.09 - 2026.12

- 基于 Vue3 + NestJS + TypeScript 全栈开发，支持 PDF/Word/Markdown 上传，自动解析、分块、向量化构建个人知识库
- 实现 RAG 检索增强问答：手写递归字符分块（段落→句子→短语三级分隔符 + 100 字重叠），bge-m3 Embedding 批量向量化（100 chunk 仅 10 次 API 调用），pgvector + HNSW 索引实现毫秒级余弦检索
- 基于 SSE 实现流式对话输出，支持 Markdown 渲染、代码高亮、中止生成、多轮上下文滑动窗口（3 轮），回答带引用溯源 [来源N]
- 认证安全：bcrypt + JWT 双 Token（15min/7d）无感刷新、Redis 会话管理、ownerId 数据隔离
- 工程化：pnpm monorepo、Docker Compose（PostgreSQL+pgvector+Redis）、GitHub Actions CI/CD 自动部署、Nginx + HTTPS
- 性能优化：highlight.js 按需引入，对话页首屏 JS 从 1054kB 降至 170kB（gzip 367→72kB）

### 一句话版本（电梯陈述）

"我做了一个 AI 知识库问答平台：上传文档自动构建知识库，提问时系统先检索最相关的资料，再让大模型基于资料流式回答，并标注引用来源——相当于每个团队都能快速做一个专属的 ChatGPT。技术上是 Vue3 + NestJS 全栈，核心是手写的 RAG 链路（分块、向量化、检索、Prompt 组装）和 SSE 流式输出。"

## 2. 逐模块讲解脚本（决策链）

### 2.1 整体：为什么做这个项目

- **背景**：2026 年 AI 应用爆发，几乎所有公司都在把 AI 塞进业务；纯 CRUD 后台没有竞争力
- **问题**：大模型直接问答会"幻觉"（编造），且不了解企业内部资料
- **方案对比**：微调模型（贵、要数据）/ 直接裸调 API（会幻觉）/ **RAG 检索增强**（轻量、可控、可溯源）
- **选择与结果**：RAG。上传文档→向量化→检索→回答，引用可溯源，幻觉可抑制

### 2.2 分块策略

- **背景**：文档不能整篇丢给模型（token 贵、检索不准）
- **问题**：怎么切块才能兼顾"语义完整"和"长度可控"
- **三方案**：固定 500 字硬切（可能切断句子）/ 语义分块（调模型判断边界，慢且贵）/ **递归字符分块**（先按段落，太长再按句子、短语逐级切）
- **细节**：500 字/块 + 100 字重叠——重叠防止答案恰好被切在边界上丢上下文；用正则 lookbehind 保留句号等标点
- **复盘**：这是 LangChain 经典方案的复刻，手写一遍才真正讲得清原理

### 2.3 SSE vs WebSocket（必问）

"流式输出我选了 SSE。原因：①场景是服务器单向吐数据、客户端只接收，用不上 WebSocket 的双向能力；②SSE 基于 HTTP，浏览器原生支持断线自动重连；③穿透 Nginx 只需 `proxy_buffering off` 一行；④复杂度低，不需要心跳和状态管理。前端用 fetch-event-source 是因为原生 EventSource 只支持 GET，带不了 Authorization 头。"

### 2.4 Embedding 工程化

- **选型**：bge-m3（中文顶尖、1024 维、免费额度大），对比 OpenAI（贵、要代理）、智谱（维度低）
- **优化**：批量——每批 10 个文本一次请求，100 chunk 只要 10 次 API 调用；指数退避重试（500ms→1s→2s）；批间限速防 QPS 触发
- **坑**：OpenAI SDK 返回顺序不保证，要按 index 重排

### 2.5 向量存储与检索

"业务数据和向量存在同一个 PostgreSQL（pgvector 扩展），省掉单独的向量数据库运维。检索用余弦距离 + HNSW 近似最近邻索引，数据量到百万级依然毫秒级返回。PRISMA 不支持 vector 类型，我用原始 SQL 迁移加列和索引。"

### 2.6 Prompt 组装（防幻觉 + 引用）

"系统提示词明确'仅根据参考资料回答，资料里没有就说没有'；检索到的资料带 [编号] 注入，模型回答时标注 [来源N]，前端展示来源片段——这解决了 AI 回答不可信的问题。历史对话用滑动窗口只保留最近 3 轮，控制 token 成本。"

### 2.7 安全

- bcrypt（换成纯 JS 的 bcryptjs 避免编译问题）
- JWT 双 Token：短命 accessToken（15min）+ 长命 refreshToken（7d，存 Redis 可作废），每次刷新轮换防重放
- 数据隔离：所有 CRUD 强制 ownerId 过滤，越权返回 404（不暴露资源存在性）

### 2.8 性能优化（要数字）

"highlight.js 默认全量引入 190+ 种语言，对话页打包 1054kB。改成 core + 按需注册常用语言后降到 170kB，gzip 后 72kB，减少 84%。"

### 2.9 部署与工程化

"pnpm monorepo 前后端类型共享；GitHub Actions 双 job（检查 + 部署），push 到 main 自动构建、SSH 到服务器、PM2 守护后端、Nginx 反代前端；HTTPS 用 certbot 自动续期。"

## 3. 高频问题与应答

### Q1：这个项目你自己写的吗？用了 AI 吗？

"骨架和核心逻辑都是我搭的，开发过程中用 AI 辅助提效——比如样板代码、报错排查。**但每一行代码我都理解**：分块算法的分隔符为什么这么定、SSE 事件协议为什么这么设计、限流重试参数为什么这么选。用 AI 提效是 2026 年工程师的基本能力，关键在于能不能讲清楚自己做了什么决策。"

### Q2：RAG 和直接调 API 有什么区别？

"直接调 API 是闭卷考试——模型只记得训练时的知识，不了解你的资料，还会幻觉。RAG 是开卷考试——先检索相关片段塞进 Prompt，让它看着资料答。好处：①回答基于你的资料，准确可溯源；②不用训练模型，成本低；③资料更新即时生效。"

### Q3：为什么不用 LangChain？

"LangChain 封装了整套 RAG 流程，但它是黑盒——面试官问'分块怎么切''检索怎么融合'我答不上来。手写核心流程（分块、检索、Prompt 组装）代码量不大，但每一步的取舍我都清楚。生产环境用框架可以，学习项目手写更能体现理解深度。"

### Q4：如果资料库有 100 万条 chunk，检索会变慢吗？

"不会，两个层面：①HNSW 索引是近似最近邻，检索复杂度近 O(log n)，百万级毫秒级；②如果还不够，可以加召回粗排——先用 BM25 或标签过滤缩小候选集，再向量精排。这也是我下一步要做混合检索的原因。"

### Q5：怎么防止模型引用不存在的资料？

"两个防线：①检索是真实发生的，引用编号来自检索结果，前端能展示原文片段——**引用可验证**；②系统提示词要求'资料里没有就明说没有'，实测无效提问时会回答'资料库中未找到相关内容'。"

### Q6：SSE 断了怎么办？

"fetch-event-source 默认支持断线重连，但 AI 流式场景我关闭了自动重连——因为回答是'一次性生成'的，断线重连后重新提问更合理，而不是续传半截回答。前端有错误提示，用户重发即可。"

### Q7：JWT 和 session 有什么区别，为什么用双 Token？

"session 服务端存状态，扩展要共享存储；JWT 无状态、天然分布式友好。但 JWT 无法主动作废，所以用双 Token：短命 accessToken 泄露面小，长命 refreshToken 存 Redis 可主动作废（登出就是删它），每次刷新轮换防重放。"

## 4. 面试禁忌

- ❌ 不要说"这个功能很简单"——每个点都要能讲出方案对比
- ❌ 不要背名词——"用了 SSE"不如"为什么 SSE 不用 WebSocket"
- ❌ 不要编数字——性能数据全部来自真实测试（打包体积、召回率）
- ✅ 主动暴露并解释边界：".doc 老格式和 PDF 扫描件 OCR 我没做，因为成本高收益低，我清楚技术边界在哪"

> 用法：对着文档把每个模块自己讲一遍（录下来听），讲不顺的地方就是没吃透的地方，回去看对应 docs/0X 学习笔记。
