# 阶段 4+：用户模型配置（BYO 大模型 API，强制自带 Key）

> 一句话：**所有 AI 功能（对话 / 研究报告）都必须用用户自己绑定的 API Key**，平台不提供任何兜底模型——用户带粮，平台只出厨房。
> 对标：Cherry Studio / LobeChat 的"自带 Key"模式（它们是桌面端本地存 Key，我们是 Web 端加密存储）。
> 迭代记录：最初是"未绑定回退系统默认模型"，用户明确要求"所有 token 消耗都是我自己的，不用我的 key"→ 改为**强制 BYO，零系统兜底**。

---

## 一、大白话：为什么是"强制"而不是"可选项"

没有 BYO 时，**每次用户提问烧的都是平台的钱**——来 100 个用户就养不起。而且用户说得对：

> "如果用户不用自己的模型，那么所有消耗的 token 都是我自己的。我只提供框架，用户要用的每个功能，首先要用户输入自己的 key，所有费用用户承担，不用我的 key。"

所以规则变成：

- 用户**必须先绑定**自己的大模型 Key，才能用对话 / 研究报告；
- 未绑定就去用 → 对话返回明确引导错误、研究报告直接标记失败并提示，**绝不静默走系统 Key**；
- 绑定入口从"个人中心"挪到**导航栏独立「模型配置」页** + 首页/对话/研究报告的前置引导横幅（用户要求"要明显告知指引用户首先要引入用户自己的模型"）；
- 平台仍承担的部分：Embedding（bge-m3 免费额度）、重排（bge-reranker 免费额度）、向量检索/Web 搜索——这些是系统级基础设施，与用户推理成本无关。

## 二、安全设计（面试重点）

| 设计点 | 方案 |
|--------|------|
| **Key 加密落库** | AES-256-GCM（密钥在服务端 env `MODEL_KEY_SECRET`，`openssl rand -hex 32` 生成；缺失时由 JWT_SECRET 派生兜底），库中只存 `iv:tag:密文` |
| **永不回传明文** | 所有接口只返回掩码 `sk-1234****abcd`；列表/详情/更新响应都不含 `apiKey` 字段 |
| **归属校验** | 配置只能本人增删改查/绑定，他人访问一律 404（数据隔离） |
| **编辑保留原 Key** | 更新时**不传 apiKey 则保留原 key**（前端表单留空），避免"改个名字把 key 丢了" |
| **解析链** | 会话绑定配置 → 用户默认配置 → 都没有 → 明确错误（无系统兜底） |

## 三、实现拆解

### 1. 数据模型

```prisma
model ModelConfig {
  ownerId   String  // 归属
  name      String  // 备注名
  baseURL   String  // OpenAI 兼容地址
  apiKey    String  // AES-GCM 密文
  model     String  // 模型名
  isDefault Boolean // 默认配置（研究报告/自主研究 Agent 用它；新建会话优先用它）
}
```
`ChatSession.modelConfigId?` 外键（ON DELETE SET NULL）——会话级绑定。

### 2. 解析规则（关键）

```
resolveForChat(userId, configId)    → 会话绑定的配置（归属校验）
resolveDefaultForUser(userId)       → 用户的默认配置（isDefault=true）

对话 askAndStream:   会话绑定 → 默认配置 → 都没有 → writer('error', 引导绑定文案) 直接返回
研究报告 processReport: 默认配置 → 没有 → 报告标记 failed（原因含"模型配置"）
查询改写 rewriteQuery: 与回答用同一个用户目标（同一 Key 计费）
```

- 视觉模型自动路由 `resolveVisionForUser`：发图时自动改用用户配置里的视觉模型（vision-exp / Qwen3-VL 等），文字对话仍用当前模型（详见 docs/27）；
- 所有 LLM 调用（回答 / 查询改写 / 报告拆分-撰写-汇总 / 自主研究 Agent）都走**用户自己的 OpenAI 客户端**；
- 服务端不再持有 `DEEPSEEK_API_KEY` 直连的聊天客户端（env 里的系统 Key 仅保留给运维/演示场景参考，业务链路不再读取）。

### 3. 接口

```
POST   /model-configs           新增（加密存储）
GET    /model-configs           列表（掩码 key）
PATCH  /model-configs/:id       更新（不传 apiKey 保留原 key）
DELETE /model-configs/:id       删除
POST   /model-configs/models    探测提供商模型列表（GET /models；创建传 baseURL+key / 编辑传 configId）
POST   /model-configs/:id/test  测试连接（最小补全请求，只返回 ok/错误信息）
PATCH  /chat/sessions/:id/model 切换会话模型（null = 跟随默认配置；已扩展为「模型配置 + 推理等级」，详见 docs/30）
```

### 4. 前端入口（按用户要求做"明显告知"）

- **导航栏**新增常驻「模型配置」入口（移动端导航面板同步）；
- **首页**：顶部醒目横幅——未绑定：「第一步：绑定你自己的大模型 API Key」+「立即绑定」按钮；已绑定：显示数量/默认配置 +「管理」；
- **对话页**：未绑定时模型下拉显示红色「未绑定模型」+ 直达绑定链接；发送后若仍未绑定，SSE 返回明确引导错误；
- **研究报告页**：未绑定时横幅引导 + 生成按钮禁用（文案"请先绑定模型配置"）；
- **个人中心**：顶部保留「去模型配置」引导条（原配置管理 UI 移出）。

## 四、面试话术

- "BYO 是**架构级决策**不是功能：个人平台承担不起 token 成本。用户带 key，平台零推理成本；而且这是用户明确的产品诉求——'所有消耗都算我的，别用你的 key'。"
- "强制而不是可选：没有兜底模型，未绑定就明确报错/跳过，绝不静默走系统 Key——既省钱也守承诺（不用我的 key）。"
- "Key 安全：AES-256-GCM 加密存储、接口永不回传明文（只给掩码）、更新留空保留原 key、他人 404。"
- "入口设计：模型配置从个人中心挪到导航栏独立页，并在首页/对话/研究报告三处做前置引导——用户第一次来就知道第一步是绑定自己的 Key。"
- "系统仍承担 Embedding/重排/检索：硅基流动免费额度，属于检索基础设施，与用户推理成本分开。"
