# 阶段 4+：检索相关性门控与"无资料"兜底

> 一句话：检索不到相关内容时，不拿噪声片段硬凑回答，而是明示"以下为模型自身知识"。
> 触发场景：问"今天天气怎么样"，知识库里全是 RAG 技术文档——之前会检索出 3 条相似度 0.36 的噪声并煞有介事地引用，现在直接判"无相关内容"。

---

## 一、大白话：问题是什么

### 用户看到的现象

1. 问了个知识库里完全没有的问题 → 回答却带了一堆"引用来源"，内容跟问题八竿子打不着；
2. 于是困惑：**没相关内容、也没联网，回答是从哪来的？**

### 真相

- **回答内容来自 DeepSeek 自身**（大模型训练时学到的基础知识）——这不是编造，是模型自带的能力；
- 但有两个毛病：
  - **检索把关太松**：向量相似度 0.36 的噪声片段（阈值 0.35 刚好放行）被当成"相关"送进回答，模型还照着引用了 [来源1][来源2]… → "没相关内容却显示引用资料"；
  - **提示词在"假装有资料"**：没检索到资料时，Prompt 里仍写着 `【参考资料】（知识库中没有检索到相关资料）`，模型措辞像在引用资料。

## 二、修复方案（两招）

### 1. 重排相关性门控（拦噪声）

召回（向量+关键词）本来就粗——它的任务是"别漏"，不是"别错"。**精排环节 bge-reranker 已经算出了精确的相关性分数，之前却只用排序、把分数扔了**。现在：

```
召回 Top-15 → bge-reranker 精排 → 分数 < RERANK_MIN_SCORE(0.1) 的片段直接丢弃 → Top-5
```

实测分数分布（bge-reranker-v2-m3）极其干净：**相关 ≈ 0.99，无关 ≈ 0.000**，阈值 0.1 一刀切开。
**宁可返回 0 条**（触发兜底），也不拿无关片段误导回答。

> 关键 BUG：原来"召回 ≤5 条"会提前返回、跳过重排——正好放走了少量噪声场景。现在无论召回多少都过门控。

### 2. "无资料"兜底（诚实回答）

- **Prompt**：没检索到任何资料时，不再写假的【参考资料】节，改为明确指示——
  > 本次未检索到任何知识库与网络资料：你可以基于自身知识回答，但必须在回答开头明确标注"（未检索到知识库资料，以下为模型自身知识）"。严禁编造来源编号或假装引用了资料。
- **UI**：回答下方显示提示条 `⚠️ 未检索到知识库资料，以上回答基于模型自身知识（可在知识库补充相关文档后重问）`，来源透明。

## 三、实测效果

| 问题 | 修复前 | 修复后 |
|------|--------|--------|
| 今天天气怎么样 | 检索出 3 条噪声（相似度 0.36-0.38），回答引用 [来源1][来源2][来源3] | 0 条引用；回答开头"（未检索到知识库资料，以下为模型自身知识）"，再正常作答 |
| RAG 的流程是什么 | 混入无关片段 | 只保留 1 条真相关片段，正常引用 |

## 四、面试话术

- "召回看召回率、精排看精确率：召回阶段宁可多召回（RRF 融合），精确性交给 bge-reranker 的**相关性分数**把关——分数低于阈值直接判无相关内容，而不是按排名硬凑 Top-5。"
- "实测校准过阈值：bge-reranker 相关≈0.99、无关≈0.00，0.1 的阈值把噪声完全切掉。"
- "无资料时的兜底策略：允许模型用自身知识回答，但**必须在开头披露** + 前端提示条，杜绝'假装有资料'的误导——这是对用户信任负责的产品决策。"

## 五、自测清单（已实测）
