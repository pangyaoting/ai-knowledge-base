# 阶段 4+：知识库文档管理大升级（项目目录上传与 Cherry 式交互）

> 一句话：把文档管理从"只能传 4 种格式、逐个传、传完还得刷新"升级成
> **全类型项目目录一键上传 + Cherry 式交互**——选择即传、环形进度、完成一个亮一个、
> 代码文件参与检索、图片等作为附件保管、多选/目录批量管理、整页代码编辑。
> 同时确立"**知识库与本地文件分离**"原则：改名/编辑/删库都不碰磁盘原文件。

---

## 一、需求来源（用户逐轮反馈，全部落地）

| # | 用户痛点/要求 | 落地 |
|---|---|---|
| 1 | 想上传整个项目（含 html 等所有文件） | 全类型入库：可解析的参与检索，其余作为附件保管 |
| 2 | 上传目录很慢 / 页面卡住 | 噪音目录过滤 + 5 路并发上传 + 单次上限 2000 |
| 3 | 上传失败（主项目目录） | **根因：全局限流 60/min 打崩批量请求** → 上传/删除/改名豁免限流 |
| 4 | 解析完要手动刷新 / 列表一卡一卡 | 增量补丁轮询：**完成一个亮一个**，不整表刷新 |
| 5 | 解析环一刷新就消失 | sessionStorage 持久化上传会话，刷新后续上 |
| 6 | 文件图标难区分 html/css/ts | 按扩展名着色 + 扩展名徽标（VSCode 文件图标配色） |
| 7 | 编辑框小、代码高亮简陋 | **整页编辑视图**：全屏、行号、语法高亮、Tab 缩进 |
| 8 | 替换时新旧并存像"增多" | 旧文档立即标记"替换中"，新文档失败自动恢复旧文档 |
| 9 | 目录要支持改名/删除、部分删除 | 目录重命名/删除 + 文件多选批量删除 + 文件夹勾选 |
| 10 | 删库/改名/编辑不应影响本地文件 | **知识库与本地分离**：磁盘原文件永不被这些操作改写 |

## 二、核心设计

### 2.1 全类型入库（"能存一个项目"）

- `detectFileType` 扩展：代码/配置文件（ts/vue/js/html/css/py/json… 约 40 种）按 `code` 类型解析；
- 不认识的类型（图片/二进制/未知扩展名）→ **附件**：入库保管、可下载、不参与检索（0 chunk）；
- 目录上传保留相对路径（`webkitRelativePath` → filename），树形展示；
- **自动跳过噪音**：`node_modules/.git/dist/build/.next/coverage/__pycache__/.idea/.vscode/.cache/.nuxt`；
- **自动跳过敏感文件**：`.env`（含 API Key）与 `*.pem/*.key`——绝不入库；
- 单次上限 2000 个文件，超限明确提示。

### 2.2 Cherry 式交互（选择即传 + 环形进度 + 增量流转）

- 选文件/目录**即自动上传**，不展示待传列表（无需滚动确认）；
- SVG **环形百分比**：上传阶段"上传中 N/M"，解析阶段"解析中 N/M"；
- **增量补丁轮询**（`mergeDocs`）：后端列表就地合并——只更新变化行的 status/error/chunk，
  不替换整个数组、不重建目录树 → **每解析完一个，那一行自己流转为"已完成"**，全程零卡顿；
- 解析会话存 `sessionStorage`，**刷新页面后环形进度与增量轮询自动续上**。

### 2.3 代码处理（参与检索）

- 代码分块器 `splitCode`：按行切、空行边界优先、**超长单行（minified）按字符窗口硬切**（避免巨无霸 chunk）；
- 每块开头标注 `文件: <路径>`，检索时模型知道片段来源；
- 代码文件原本跳过"知识图谱抽取"以省一次 LLM 调用——**知识图谱功能已于 2026-08-30 整体移除**（`1b6949a` + 迁移 `drop_knowledge_graph`，详见 docs/19），该条已无意义；
- **二进制误判兜底**：UTF-16/伪装扩展名的二进制解码后垃圾占比高 → 自动转附件，不报解析失败。

### 2.4 文件图标与编辑

- 图标按扩展名着色（HTML 橙 / CSS 蓝 / TS 蓝 / VUE 绿 / 图片粉 / 压缩包琥珀…40+ 映射）+ 扩展名徽标；
- 编辑 = **整页视图**（替代列表，非弹窗）：语法高亮（注释/字符串/关键字/数字）、行号、不换行横向滚动、Tab 缩进；
- 编辑只更新知识库内分块/向量，**不改写磁盘文件**。

### 2.5 目录与多选管理

- 目录行：✏️ 重命名（批量改路径前缀，含冲突检查）、🗑 删除（其下全部文档）、复选框（勾选=选中其下所有文件含子目录）；
- 文件行复选框 + 顶部"已选 N 个 · 删除选中"批量删除条；
- 目录删除/重命名/批量删除均 **6 路并发** + 接口幂等（404 视为成功）。

### 2.6 替换语义（"替换"不是"增多"）

- 上传同名文件：**旧文档立即标记 `replacing`（替换中）**，列表显示蓝色"替换中"徽标；
- 新文档解析成功 → 旧文档删除；**解析失败 → 旧文档自动恢复 done**（不丢数据）。

## 三、自测结果

| 项 | 结果 |
|---|---|
| 80 个文件并发上传 | 0 个 429（限流豁免生效） |
| 压缩单行 JS（5000 字符一行） | 切成 8 块（不再巨无霸） |
| UTF-16 txt | 自动转附件（done/bin/0 chunks），不报解析失败 |
| 代码文件（.ts） | fileType=code，chunk 带"文件: 路径"前缀 |
| 附件（png） | 原样保管，0 chunks |
| 同名替换 | 旧文档标记"替换中"，成功后删除 |
| 目录路径保留 | `src/components/AppButton.ts` 树形展示 |
| 构建 | 双端 vue-tsc/nest build EXIT=0 |

## 四、踩坑（这个功能教会我的）

1. **全局限流是批量操作的最大暗坑**：60/min 对"上传几百个文件/删除几百个文档"是死刑——批量接口必须 `@SkipThrottle()`（限流的意义是防刷登录，不是防合法批量）；
2. **"刷新"的真问题不是频率，是整表替换**：早期轮询把 `list.value` 整体替换 → 全表重绘 → 卡顿；
   改成**就地补丁**（只改变化的行）后，高频轮询也不卡；
3. **待传列表渲染几百上千行 = 卡死**：Cherry 式"不展示待传列表"从根上解决；
4. **压缩单行代码**：按行切分块器对 minified 文件失效（一行 = 一个巨块）→ 必须加超长行硬切；
5. **lucide 的 `File` 图标会遮蔽全局 `File` 构造函数**：`new File()` 直接类型错误 → 导入必须别名 `File as FileIcon`；
6. **编辑内容重写磁盘文件**：早期"文件=唯一事实来源"设计导致编辑污染原文件 → 改为"知识库与本地分离"后下载永远是原始文件。
