# 阶段 4+：文档预览与引用定位

> 一句话：回答附带的每条引用都能**点开原文、跳到出处段落并高亮**，回答可溯源、可信。
> 对标：ChatPDF / Dify 的"引用可点击溯源"。

---

## 一、大白话：这个功能解决什么问题

AI 回答带了引用来源，但用户只能看到一小段文字。**凭什么信你？** 点一下引用就能看到原文上下文，这是 RAG 产品建立信任感的关键一步——"你说的话我能在原始文档里核实"。

本功能 = 两件事：

1. **文档预览**：知识库页预览入口已移除（bf50a0a），当前预览入口在**对话页/研究报告页**——右侧滑出抽屉，按"第 1 段、第 2 段…"展示文档的全部文本块；
2. **引用定位**：对话页/研究报告页点任意「来源N」，抽屉自动打开对应文档，滚动到被引用的那一块并高亮闪烁。

## 二、方案对比（为什么选 A）

| 方案 | 预览内容来源 | 引用定位方式 | 结论 |
|------|-------------|-------------|------|
| **A（采用）** | 直接返回该文档的**全部文本块**（chunks，按 chunkIndex 排序） | 引用里的 chunkIndex 就是文本块序号，**天然对齐**，直接滚动高亮 | 预览和定位同源，实现简单可靠，Dify 同款思路 |
| B | 重新解析原文件得到**完整原文** | 在原文里**搜索** chunk 内容子串再高亮 | 原文段落边界和检索块不一致，分块截断/空行差异导致定位脆弱、慢 |

**选 A 的核心洞察**：检索的"最小单元"就是文本块，引用指向的也是文本块——预览按同一单元展示，就不存在"对不上"的问题。代价是预览看到的是切块后的文本（无 PDF 分页排版），对知识问答场景完全够用。

## 三、实现拆解

### 1. 后端：文本块预览接口

```
GET /knowledge/documents/:documentId/chunks
→ { filename, fileType, chunks: [{ id, chunkIndex, content }] }   // chunkIndex 升序
```

设计要点：

- **按 documentId 直取**，而不是按知识库嵌套：聊天引用来源里只有 `documentId`（没有知识库 id），且历史消息里的旧引用也没有 kbId——按文档 id 取，新旧数据通吃；
- **归属校验**：`document → knowledgeBase → ownerId` 不是当前用户 → 404（沿用全局数据隔离原则）；
- 返回 `chunks` 数组而非拼接大字符串：前端逐块渲染，引用定位天然是"第 N 段"。

### 2. 前端：DocPreviewDrawer 复用组件

`apps/web/src/components/DocPreviewDrawer.vue` —— 右侧抽屉（Teleport 到 body），**对话页和研究报告页共用**（被 Chat.vue 与 Research.vue 引用）：

- Props：`documentId`（非空即打开）、`highlightChunkIndex`（定位目标块）；
- 打开时拉取 chunks，渲染"第 N 段"卡片（`data-chunk` 属性标记）；
- 定位逻辑：`scrollIntoView({ block: 'center', behavior: 'smooth' })` + 高亮**常驻显示**（边框+底色），到达时播放入场闪烁动画（1.4s 光圈），切换引用时通过"先清后设"重新触发动画；
- 边界：文档还在解析（chunks 空）→ "还在解析中"；跨文档切换 → 重新拉取；同文档换块 → 只重新定位不高亮逻辑复位。

### 3. 两个入口（收敛为一个）

| 页面 | 入口 | 定位参数 |
|------|------|---------|
| 对话引用来源 | 每条来源变成可点击条目（悬停高亮 + 提示文案） | `chunkIndex` 精确定位 |

> 演进记录：最初知识库文档列表也有「预览」按钮，但"按文本块浏览"对读原文意义不大，
> 且与编辑弹窗/下载功能重叠 → 按用户反馈移除（bf50a0a）；此后预览入口收敛为**对话页 + 研究报告页**
> 两个场景共用（DocPreviewDrawer 被 Chat.vue 与 Research.vue 引用），不再服务知识库页，UI 更干净。

## 四、面试话术

- **为什么这个设计好**："检索最小单元 = 文本块，引用和预览用同一个单元，杜绝了'定位对不上原文'这类不可信体验，也是 Dify 的做法。"
- **组件复用**："预览抽屉做成独立组件，对话页 + 研究报告页两个场景共用（DocPreviewDrawer 被 Chat.vue 与 Research.vue 引用），加一个 `highlightChunkIndex` prop 就获得定位能力。"
- **数据兼容**："老消息里的引用没有知识库 id，接口设计成按 documentId 取，后端自己解析归属，新旧数据一套代码全兼容。"
- **可量化**："回答引用溯源零跳转成本（一次请求 + 一次滚动），抽屉组件 gzip 约 2KB。"
